## 0. 结论先说

**行。但"完全零改动"做不到**：主程序总得有一个挂载点。
可以压到 ——

> **现有业务文件一个都不改**：只做 1 次文件重命名（内容一字不动）+ 2 个新文件；

## 2. 方案：启动时分流，不碰运行时

核心是**不在 ArenaApp 跑起来之后换模组，而是在它启动之前决定这次跑谁**。
`ArenaApp` 没有整体销毁接口，硬做卸载必然要改它 —— 那就污染了。
改 URL + reload 是项目已经在用的成熟路径，零风险。

```
arena.html（不改）
   └─ /src/arena/main.ts  ← 变成 6~10 行「分流器」
        ├─ 无 ?mod=  →  await import('./vanilla')     ← 原 main.ts 原封不动
        └─ 有 ?mod=  →  await mountMod(id, host)
                          ├─ fetch /mods/manifest.json
                          ├─ import(/* @vite-ignore */ '/mods/grand-map/index.js')
                          └─ mod.mount(host)  ← 模组自带规则层/渲染层
```

菜单怎么进：模组按钮由 `modHost` 在 vanilla 启动后**往 `.start__row` 追加一个 DOM 按钮**，
`StartMenu.ts` 一行都不用改；点击 → `location.search = '?mod=grand-map'` → reload。
模组里点「退出」→ `location.search = ''` → 回主菜单。

**所以"热插拔"的生命周期 = 一次 reload，不需要 ArenaApp 支持卸载。**

### 2.3 契约（已落地，实现在 `modHost.ts` / `modDeps.ts`）

```ts
// mods/manifest.json
{
  "version": 1,
  "mods": [
    { "id": "grand-map", "name": "大地图 · 多方混战",
      "entry": "index.js", "api": 1, "remote": null }
  ]
}

// 模组导出
export interface GamekarMod {
  mount(host: ModHost): void | Promise<void>;
  unmount?(): void;              // reload 前清理事件监听 / rAF，可省
}

// 主程序注入的最小面：模组**不静态 import 主程序任何模块**
export interface ModHost {
  readonly api: 1;
  readonly canvas: HTMLCanvasElement;   // #arena-stage
  readonly uiRoot: HTMLDivElement;      // #arena-ui
  readonly three: typeof import('./modDeps').modThree;  // 具名子集，不是完整命名空间
  readonly engine: typeof import('./modDeps').modEngine; // 只借引擎，不借玩法
  readonly services: {
    toast(msg: string): void;
    makeLoop(opts: GameLoopOptions): GameLoop;
  };
  exit(): void;                        // 清 ?mod= 并 reload
}
```

依赖注入是关键：`three` 和引擎工具由 host 传进来，模组自己**不 import**。
这样模组既不用重复打包 500KB 的 three，也不会把主程序的 chunk 关系搅乱。
分流器只在 `?mod=` 时才 `await import('./modDeps')` 组装依赖 —— **普通对战零额外加载**。

动态 import 必须写成变量 + `/* @vite-ignore */`，否则 Vite 会在构建期去解析这个路径：

```ts
const url = `/mods/${encodeURIComponent(id)}/${entry}`;
const mod = await import(/* @vite-ignore */ url) as GamekarMod;
if (mod.mount) await mod.mount(host);
```

`api` 版本号不匹配就拒绝加载并退回主菜单 —— 防止旧模组把新版主程序搞崩。

### 2.4 包体积：`import('three')` 是个陷阱（实测）

第一版在 `modHost` 里直接 `await import('three')` 拿命名空间对象注入，构建出来：

| chunk | 改前（P-082） | 第一版模组化 | 修完 |
| --- | --- | --- | --- |
| `three-*.js` | 496.25 kB | **689.59 kB（+39%）** | **497.03 kB（+0.16%）** |
| `vanilla/arena-*.js` | 184.23 kB | 185.04 kB | 184.33 kB |

原因：动态 `import('three')` 会把整个命名空间对象钉住，Rollup 没法 tree-shake ——
**模组一行玩法没写，主程序首包先胖了 193 kB**，这跟"别污染主程序"正好相反。

修法是新增 `src/arena/modDeps.ts`：只**具名**列出模组用得到的类，导出
`modThree` / `modEngine` 两个对象，`modHost` 动态 import 的是这个文件而不是 `three`。
结构锁里有一条反证：`modHost.ts` 里再出现 `import('three')` 必须红。

代价是**注入面收紧**：模组只能用 `modThree` 里列过的类。本次就真踩了一次 ——
占位模组改成用 `T.Group` 统一旋转后，忘了把 `Group` 加进白名单，
`mount()` 抛 `T.Group is not a constructor`，host 正确兜住画了「模组没挂上」回退页。
现在 `tests/mod_isolation_20261108.test.ts` 会扫模组里所有 `T.X`，
断言每一个都在 `modDeps` 白名单里（带反证）。**加新类 = 在 modDeps 加一行**，仍然是注入。

## 3. 隔离红线（防"污染"的具体判据）

1. **模组不许 import `@arena/ArenaWorld` / `config.ts` / `ArenaApp` / `ArenaHud`**。
   理由：前两者是单例常量与二值 `Side`，一引用就等于要改主程序；后两者会抢同一个 canvas。
   六方 / 外交 / 商路规则**全部写在模组内部**。
2. **模组不进主 bundle、不被主测试执行**：`src/` 里不许有指向 `mods/` 的静态 import。
   `tests/mod_isolation_20261108.test.ts` 只是**读模组文本做静态断言**（不是 import / 执行），
   这是结构锁，不算把模组焊进主套件。模组自己的测试放 `mods/grand-map/tests/`，单独跑。
3. **主程序不留任何模组专属分支**：`mode` 枚举不新增 `grand`，`StartMenu` 不写死"大地图"。
   分流器只认 `?mod=<id>`，具体 id 一律从 manifest 来。
4. **默认零影响**：没有 `?mod=` 时清单缺失 / 读失败只是不注入菜单按钮，vanilla 照常开；
   有 `?mod=` 但清单缺失 / api 不匹配 / import 报错 ⇒ 画一块自包含的回退页
   （带「返回主程序」），只打 console.warn，**绝不抛到顶层、绝不把主程序拖下水**。
5. **锦标赛图一个数不动**：模组自带经济 spec，绝不改 `ECONOMY` / `FIELD` / 射程表。

## 4. 手机端的硬约束（这条必须提前说）

`public/mods/` 会随 `cpSync(dist → dist-android)` 一起打进 APK，所以"随包分发"天然成立。
但 **Capacitor WebView 的 `https://localhost` 指向 APK 内只读 assets，
装完之后没法往里丢一个新文件就让它出现**。所以"作为模组来更新"分三档：

| 档 | PC 桌面 | 安卓 APK |
| --- | --- | --- |
| 随包 | 丢进 `public/mods/` + 改 manifest，**刷新即生效，不用重编译** | 重打 APK 时带上（主程序 JS 不用重编，但 APK 要重装） |
| 增量更新 | 同上 | 需 **远程 HTTPS URL**：manifest 里填 `remote`，host 优先加载远端并缓存；断网回退随包版本 |
| 完全离线热更 | 同上 | 要接 Capacitor Filesystem 写到外部可写目录再 `blob:` import —— Android WebView 对 blob import 有限制，**待验证，不建议第一版做** |

安全：动态 import 远程 JS = 远程代码执行。远程更新必须固定可信 HTTPS 域名，
并在 manifest 里带 `sha256`，fetch 后校验文本再加载；`allowMixedContent: false` 已开，别改。

> **要拍板**：手机端接受"随 APK 一起更新"，还是要"联网增量更新"？
> 这一条决定 `modHost` 第一版要不要写远程加载与校验。

### 10.2 新增的「开放 API」出口

之前 `modHost` 只注入 `three / engine / assets`，模组要复刻主模式观感只能自己造 DOM，
于是做成了「另一个战争模式」。P-087 加一层**单向能力出口**：

```
src/arena/modApi.ts          ← 唯一新增的 src/ 玩法侧文件（只读 config + cardIcons）
   ├─ MOD_API_VERSION = 2
   ├─ CARDS / ECONOMY / HAND / iconOf        （只读，主程序卡池是唯一来源）
   ├─ ModCard extends ArenaCard { icon? }     （扩展卡自带图标，不改 CARD_ICON）
   └─ createModHand(cb) → ModHand             （四张 .ahud__card，复用 arena.css）
          ↓ modDeps.ts 具名导出 modApi
          ↓ modHost.ts 注入 host.modApi
public/mods/grand-map/hand.js                 （判据 / 扣钱 / 补牌全在模组里）
```
