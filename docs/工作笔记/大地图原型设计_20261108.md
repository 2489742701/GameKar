### 1.1 经济模型和 1v1 是反过来的（这条最值得先说）

| | 锦标赛 1v1 | 大地图 |
| --- | --- | --- |
| 金币性质 | **流量**：慢慢来，逼你想清楚每栋楼 | **存量**：开局一桶 50 金是主要本钱 |
| 主约束 | 建筑协调经济（民居/磨坊配给） | **商路安全**（钱要靠守路才再生） |
| 开局 | 15 / 30 | **50 / 50（满）** |
| 自然恢复 | 2 秒 +1 | 特慢（候选 12~20 秒 +1，或直接接近 0） |
| 再生来源 | 自然跳格 + 磨坊 | **集市 + 贸易路线**（商队到站才结算） |
| 风险 | 攒钱铺楼会冲垮配给约束 | 商路被劫 ⇒ 断供 ⇒ 存量花光就没得打 |

也就是说：1v1 的钱是"水龙头"，大地图的钱是"存折 + 一条要护送的运钞线"。
**不能把 1v1 的 `ECONOMY` 常量改成 50 就直接开跑** —— 那会同时毁掉锦标赛图。

### 1.2 外交、商路、军事要闭成环

```
集市 ──(商队沿商路)──► 对方/中立集市 ──► 结算金币（ replenish 存量）
  ▲                          │
  │                          ├── 穿过敌对领地 ⇒ 被劫 ⇒ 断供
  └──── 派兵护航 ◄───────────┘
            ▲
            └── 结盟 ⇒ 商路可通行 / 互不攻击 ⇒ 少一处分兵 ⇒ 更容易守
```

这就是"管理更复杂"的来源：**结盟不是纯外交姿态，它直接改变你要分多少兵去护路**。
原型阶段最值得验证的就是这一条闭环的手感，而不是地图有多大。

### 1.3 六芒星布局：固定的是路网，可变的是关系

用户把三件事一起给了：6 方按六芒星坐落、商路开局固定、中间那片谁抢到是谁的、
近的集市钱少远的钱多。**这四句在六芒星几何上正好自洽** `[推]`：

```
            顶点 A
          ╱        ╲           · 6 个顶点 = 6 座主城
     顶点 F ── 中心 ── 顶点 B  · 6 条相邻边 = 近程商路（不穿中心，安全、钱少）
      ╲   ╲      ╱      ╱   ╱   · 3 条对径长弦（A–D / B–E / C–F）
       ╲   ╲    ╱    ╱   ╱     = 远程商路（穿过中心，钱多、要护航）
        顶点 E ──── 顶点 D     · 中心 = 公共可建区
            顶点 C
```

- **6 条边**：相邻两家，路短、不经过中心 ⇒ 天然"近、安全、钱少"。
- **3 条长弦**：对顶点两家，必穿中心 ⇒ 天然"远、钱多、要护"。
- **中心公共区**：谁抢到就能卡住 3 条远路 —— 于是"抢中间"和"赚大钱"变成同一件事，
  不需要再额外写一条规则去逼玩家争中心。

> `[推]` 以上连法是我按六芒星推的候选，**不是用户原话**。要确认是不是"6 边近 + 3 弦远"。

另一个必须分清的点：**固定的是路网拓扑，可通行的是关系**。
6 条边 + 3 条弦开局就在那里，但按规则 8 只有"中立 / 盟友"方向才走得通；
一旦某方向变敌对或死仇，那条路立刻封死。所以扣押不是"抢一车货"这么简单 ——
**它同时永久砍掉自己一条财路**（死仇不可结盟，路再也开不回来）。

### 1.4 集市界面：一次「贪婪 vs 长期现金流」的抉择

交互入口（用户："需要点开集市设置"）：点自己的**集市** → 面板里做两件事：

| 分组 | 面板里做什么 | 后果 |
| --- | --- | --- |
| 发车 | 选目的地（中立 / 盟友的集市）、看近/远两档收益、派商队 | 到站结算金币，中途被劫则断供 |
| 收货 | 中立方向拉来的车：**正常贸易** 或 **扣押** | 贸易＝持续现金流；扣押＝一次性拿走 + **立即死仇、永不可结盟** |

规则 6「联盟最多 2 人」在这里变成硬约束：玩家最多只有 1 个盟友，
所以"远的钱多"基本只能从**中立方向**拿 —— 而中立方向又随时可能被自己扣押成死仇。
**越贪越富、也越快把财路砍光**，这个取舍是整套经济最值得先做出手感的地方。

### 1.5 中心区辐射占领 · 道路封死（14:22 新增）

这轮三条是**空间规则**，放在一起才成立：

**① 中心区是"辐射解锁"，不是"先到先占整片"**

```
  · · · ▓ ▓ · · ·        每格三种状态：未解锁 / 我方可建 / 他方可建
  · ▓ ○ ▓ ○ ▓ ·          ○ = 已放下的建筑
  · · ▓ ═ ═ ▓ ·          ═ = 道路格（恒不可建，也不参与辐射解锁）
  · · · ▓ · · ·          ▓ = 被邻近建筑"辐射"解锁的格子
```

可执行版 `[推]`（细节待定）：每方从自己主城朝中心的一侧有起点格 →
放下一栋楼 → 把它**邻域**里非道路的格子标成"我方可建" → 继续往外摊。
两方辐射圈重叠时按「谁抢到就是谁的」判先到先得。
`[待]` 邻域取 4 邻还是 8 邻、解锁格会不会被对方反抢。

**② 道路格的三重属性**

| 层 | 规则 | 含义 |
| --- | --- | --- |
| 建造 | **恒不可建** | 不能拿楼把商队堵死，路网拓扑永远是开局那张 |
| 单位 | **军队可以站上去拦** | 拦路是**军事行为**：要派兵、要养、会被打掉 |
| 判定 | **左右两侧皆敌 ⇒ 封死** | 封路是**地盘层判定**：自动、持续，不用派兵也过不去 |

所以要分清两件事：**"封死"是地盘状态**（因为两侧被敌人辐射占领了），
**"拦路"是一次动作**（派一队兵站路上，抢一票货）。前者靠抢中心解决，后者靠护航解决。

**③ "左侧和右侧都是敌人"的解读** `[解读待核]`

我按**路段级**理解：把每条商路切成若干路段，每个路段看它左右两侧相邻地盘的归属；
两侧都属于敌对 / 死仇 ⇒ 该路段判封死，商队到段口就得回头。
单侧是敌人 ⇒ 路还通，但对方能派兵上来拦（规则 17）。

> 如果你指的是**六芒星上我左右两个相邻顶点势力都是敌人 ⇒ 我这条路封死**，
> 那判据要换成"顶点级"，比路段级粗一档。两种写法在 §4 里留着，等你核一句即可。

这条和「背刺 = 死仇」合起来很硬：盟友一旦背刺，不只是多一个敌人，
**是永久失去那一段路的通行权**，而且再也不能靠结盟找补回来。

## 3. 最小可玩原型（P0）建议边界

只验证「外交 ↔ 商路 ↔ 分兵」这一条闭环，其他一律不做（YAGNI，等第二个用例再抽象）。

**做：**

1. 独立模式 `?mode=grand`，菜单多一个入口；锦标赛图仍是默认，一个数不动；
2. 一张大图（尺寸待定）+ **6 个势力按六芒星坐落**（1 玩家 + 5 AI）+ 中心公共区
   **辐射解锁**（放一栋楼 → 邻域解锁 → 可接着往外摊）；
3. **固定路网**（6 边近 / 3 弦远，待确认）+ 商队单位：按关系决定能否通行，
   到站结算金币；**道路格恒不可建**、**左右两侧皆敌自动封路**、**军队可站路上拦**；
4. **集市界面**：发车（选目的地 / 近远两档）+ 对中立来车「正常贸易 / 扣押」；
5. **外交四态**，点主城开面板；盟上限 2；**背刺与扣押同为死仇、永不复盟**；AI 有最简反应；
6. 独立经济 spec：50 / 50 / 极慢恢复 / 近少远多；
7. **功能性建筑 P0 只做集市一种**，其余等用户点名再排期（不擅自铺开）；
8. 胜负先占位：敌对主城全拆 或 计时积分（具体判据见 §4）。

**不做（P0 明确排除）：** 联机 / 卡牌成长与解锁 / 科技树 / 昼夜色温 /
多套主题地形 / 复杂 UI 皮肤 / 商队升级 / 功能性建筑全家桶。
> 注意：「背刺」已从排除项里**移出** —— 用户 14:13 明确要，属于 P0。

## 4. 待拍板清单（这轮不猜）

三轮下来已定死的：几方 / 结盟上限 / 背刺=死仇 / 商路固定 / 集市界面 / 扣押 /
近远收益 / 中心辐射占领 / 道路不可建 / 军队可拦 / 两侧皆敌封路。
用户 14:13 说"**先这样，看看**"，14:22 又主动补了四条 ⇒ **仍不开工、不追问**，只列清单。

1. **"左侧和右侧都是敌人"是哪一级判据**（§1.5 `[解读待核]`）：
   我按**路段级**（每个路段看左右两侧地盘归属）写的；若你指六芒星上
   **我左右两个相邻顶点势力**都是敌人，判据要换成顶点级。这句最值得核。
2. **辐射的细节**：邻域取 4 邻还是 8 邻？解锁格会不会被对方反抢？
   每方中心区起点格怎么给（自家主城朝中心那一侧一格？）？
3. **军队拦路的后果**：抢走这票货 / 毁车 / 只是卡住一段时间？
   被拦的商队能不能派兵救回来？拦截方要不要承担外交后果？
4. **"商路中立和盟友"是"只能"还是"优先"**：敌对方向完全不能发车，
   还是能发车但必被劫？（这决定死仇是"砍一条路"还是"多一个敌人"）

## 7. P-085 方向修正：接入主游戏 3D（2026-11-09）

> ⚠️ **本节仍未做完**：P-085 只借了两个模型工厂，地面/地形/看台/光照/相机/后期

用户纠正：「**我想你可能错误地理解了这个，我们这你直接把这个原型做成游戏了，

追问后补：「**接入主游戏 3D，注意是以模组的形式接入。通讯怎么写你随便，
只要不要污染主游戏就行，要可以撤回的那种，或者你提个 Git**」。

### 7.1 纠正了什么

P-084 把原型做成了**一个独立的 2D 小游戏**（SVG 棋盘 + 右侧发车/结盟面板 + 结算），
这是错的。正确口径：

| | 错（P-084） | 对（P-085） |
| --- | --- | --- |
| 原型的定位 | 当成可玩成品继续堆 | 只是把规则讲清楚、摸清楚的工具 |
| 玩法归属 | 另起一套 2D UI 的独立游戏 | **长在皇室战争那个 3D 游戏里**，同一套场地/建筑模型/单位/HUD |
| 工程形态 | 独立模组 | **仍是模组**（用户重申），但视觉与玩法表现必须和主游戏一致 |
| 通讯 | 无 | 随便设计，只要不污染主游戏 |
| 撤回 | 无 | Git 可整体撤回 |

### 7.2 可撤回性：独立分支

所有改动放在 **`feat/grand-map-3d`** 分支，从 `master`（P-084 之后）拉出。
撤回 = `git checkout master`，或者 `git revert <该分支唯一提交>`。
`master` 上保留的仍是 P-083 模组壳 + P-084 规则原型，不受影响。

### 7.3 通讯层（没有动任何玩法文件）

只扩了 `src/arena/modDeps.ts` 这个 P-083 新建的"模组依赖出口"：

- `modThree` 补齐 3D 需要的具名导出（AmbientLight / DirectionalLight / Raycaster /
  PlaneGeometry / SphereGeometry / ShaderMaterial / CircleGeometry / Color 等）；
- 新增 `modAssets = { ARENA_MODELS, buildModel }` —— 把主游戏的**模型工厂注入**给模组，
  模组里的大本营/民房和 `/arena.html` 1v1 是同一套模型；
- `modHost.ts` 的 `ModHost` 加一个只读 `assets`，`makeHost()` 里一并注入。

模组依然**零静态 import**（隔离锁一条没松），只是从"只用引擎"扩到"也用主游戏视觉资产工厂"。
three 共享 chunk 实测 **497.03 → 497.15 kB**，vanilla 反而 184 → 173 kB（模型代码拆成共享 chunk）。

### 7.4 3D 场景与天空盒

`view.js` 从 SVG 换成 three 场景：正交俯视机位（对齐 1v1）、圆形战场、
6 座主城用 `ARENA_MODELS.core`、中心 9×9 可点格子用 Raycaster、放楼用
`ARENA_MODELS.house`、固定商路用 LineSegments、商队是沿路插值的小方块。

`sky.js` 是**同一场景内的天光层**，不是独立预览页：

- 天空盒：`SphereGeometry + BackSide + 渐变 ShaderMaterial`；地面改成圆形，
  四角露出天空渐变，四时段底色才真的可见；
- 云朵：4 个圆面片 + 1 个扁平面片拼成的**面片小模型**，水平铺在高空四角，
  俯视可见、缓慢飘动、随时段改色；
- 四时段：白天 / 中午 / 黄昏 / 晚上，切换即时生效；光照颜色强度 +
  天空渐变 + 云色 + 一层 DOM 色调覆盖（`tint`）一起变。
  > 主游戏是正交俯视，抬头看不到天；地面又是 Basic 材质不吃光照，
  > 所以时段差异主要靠**圆形战场外露的天空 + tint 覆盖**表达，
  > 这也和 P-077 留的 `dim` 通道是同一条思路。
