# 科技前置与齿轮工厂——设计（2026-11-07）

用户："现在建造科技有前置要求：想要造军队，默认只能造一个军队，就是**民兵集结**，
由 6 个小小单位组成（4 近战 + 2 弓箭手），攻击/防御低、人多、价格便宜。
**必须建造军营才能解锁更多军队**。**想要建造空中单位，需要齿轮工厂**。
帮忙设计一下：一个大齿轮在那转转转，工厂样式但比较复古，你先设计，设计好之后
我在游戏内看，工厂稍微大一点，可能要占地 **4×3**。"

## A. 科技前置：一张表管全部

| 想造什么 | 前置 | 判据 |
| --- | --- | --- |
| **民兵集结**（唯一默认军队） | 无 | 永远在卡池 |
| 其它**地面军队**（含弩车/火炮） | **兵营** | 己方有 ≥1 座**完工**的兵营（`build>=1 && hp>0`） |
| **三架飞行器**（热气球 / 空气螺旋机 / 扑翼轰炸机） | **齿轮工厂** | 己方有 ≥1 座**完工**的齿轮工厂 |
| 建筑卡 | 无 | 但受「场地有没有对应尺寸空位」裁量（P-056 的判据） |

- **施工中不算解锁**（项目红线：施工中的楼不干活）；建筑被拆 → 立刻重新上锁，
  手牌里不满足前置的卡当场换成允许卡（只换卡面，槽位/冷却不动）；
- 蓝红双方同一条规则（AI 也必须先盖兵营）；
- 解锁是**发牌层过滤**，不是「卡变灰」：池子外根本抽不到，玩家不会被一堆
  点不动的卡占手牌；
- HUD 小标按状态给提示：「需要军营解锁军队」/「需要齿轮工厂解锁空军」/
  「场地已满 · 只发军队」（优先级：场地 > 兵营 > 空军，按解锁顺序）。

## B. 民兵集结（默认军队卡）

| 项 | 值 | 为什么 |
| --- | --- | --- |
| 价格 | **5 金** | 最便宜的卡，开局 8 金就能出 |
| 编成 | 4 民兵 + 2 弓箭手 = **6 人** | 用户指定「4 近战 2 弓箭手」 |
| 民兵数值 | hp22 / 攻5 / 防0 / 射1.2 / 速1.5 / 间1.1 | 明确"攻防低"，靠人数 |
| 弓箭手 | 沿用现有 archer（hp26/攻7/射4.2） | 复用，不另造数值 |
| **容器口径** ⚠️ | 6 人口 + **3 面包**（每人 0.5 面包） | 基础容器是 6 人口 / 3 面包，6 人×1 面包会**一张卡都放不下**；民兵自带干粮、半份口粮，正好压满基础容器，也保留"先盖民居/磨坊"的主线 |

- 实现：`ArenaCard.breadPerMan?: number`（默认 1）、`ArenaUnit.breadCost?: number`；
  `supplyOf` 按单位累加 `breadCost`，`supplyBlocked`/`canPlay` 按卡算，
  卡面两行需求也按「实际面包数」画（不是按人头 ×6 骗人）；
- 卡池新增第 24 张卡；民兵是**唯一**无前置军队卡。

## C. 齿轮工厂（4×3，复古 + 大齿轮）

### 占地与数值

| 项 | 值 |
| --- | --- |
| 占地 | **4 列 × 3 行**（第一栋非 3×3 建筑） |
| 血量 | 700（比普通楼厚一点，科技建筑值得拆） |
| 价格 | **16 金**（与炮塔同档，解锁空军要有代价） |
| 后勤 | **不需要民居**（被动科技，不开火不产兵；`needsStaffing` 不加它） |
| 人口 | 占 2（所有建筑统一），同样吃「给军队留 2 格」的槽位制衡 |

### 模型（2026-11-07 下午返工，原设计已被实机推翻）

用户原话："工业工厂穿模了，其次要求它没那么高，可以稍微矮一点，有两个烟囱，有齿轮转"。

**原版量出来的三处硬伤**（视图把模型乘 `BUILDING_SCALE=2.2`，工厂当时还额外乘 1.18 = 2.596）：

| 项 | 原版 | 占地/约束 | 后果 |
| --- | --- | --- | --- |
| 台基宽 | 2.3 × 2.596 = **5.97 格** | 4 格 | 屋顶/台基盖到隔壁格子 |
| 齿轮中心 z | 0.95 × 2.596 = **2.47 格** | 半深 1.5 格 | 整个轮子悬在墙外、下缘插进台基 |
| 总高 | 2.72 × 2.596 = **7.06 格** | 大本营才 6.4 格 | 鹤立鸡群 |
| 旗位 `base` | **2.25 格** | 屋顶在 4.9 格以上 | 旗杆整根从砖墙里长出来 |
| 施工外壳 | `y0=0.06, h=1.15` | 砖墙 `0.48~1.63` | 施工时半截墙和实体墙完全错位 |

**现在按占地倒推**（模型单位 = 格 / 2.2）：x 半宽 ≤ 0.909、z 半深 ≤ 0.682，
实测取 0.86 / 0.60，含齿轮最远 z = 0.60 → 1.32 格仍在 1.5 格内。

- 预览器实测 **3.8 × 2.7 格 · 高 4.1 格**（原 5.97 × 3.89 · 高 7.06）；
  额外那道 1.18 缩放已从 `ArenaApp` 的**真楼和拖放影子两处**删掉，全楼统一 2.2；
- **两根烟囱**：左右各一根，底部埋进屋顶 0.1 不留穿缝；
- **两枚齿轮贴在前墙**（墙皮 z=0.52，盘厚 0.08 ⇒ z 0.52~0.60，既不插墙也不悬空）：
  大轮 12 齿 4 辐条 `speed:+0.9`、小轮 8 齿 `speed:−1.5`（反向且按半径比更快 ⇒ 看着真在啮合）；
  28 个自转件共用 `spin/pivot` 机制，`syncParts` 每帧按绝对角度推进（探针 1 秒读数
  0 → −9.99，速度集合 `[0.9, −1.5]`）；
- 门挪到右边、窗开后墙，给齿轮让出整片前墙；施工外壳与砖墙同轮廓同高度；
- 旗位 `base=3.35 / pole=1.1`，立在屋脊侧，不再从墙里穿出来；
- 截图：`docs/齿轮工厂返工_20261107.png`。

### 唯一建筑：场上有自家工厂就不再发这张牌

用户："如果场上有一个工业工厂，玩家不会再被发到这个手牌，除非自己的工厂被摧毁"。

判据只有一处：`ArenaWorld.techAllows()` → `hasFactory(side)`。抽卡、刷新、补牌、
拆楼后的 `purgeLocked` 全都经过它，UI 不再重算一遍。

- `hasFactory` **连施工中（build<1）都算**：工厂一落地就吃掉一个 4×3 的坑，
  第二张工厂卡在它盖好之前根本没地方放，发下来就是死牌。这和 `hasBuilt`
  要求完工是故意的区别 —— 一个是"能不能解锁"，一个是"有没有占坑"；
- 「被摧毁」不需要额外标记：`hurtBuilding` 打空血时 `buildings.delete(b.id)`，
  楼一没判据自然 false，工厂卡自动回卡池（**废墟 `ruins` 不算楼，不拦发牌**）；
- 只锁自家：红方照常能拿；PVE 双人同阵营共享建筑，一人建厂两人都不再发。

### 4×3 牵动的判据（全部参数化，不写死 3）

- `buildingPlacementIssue(side,col,row,cols,rows)`、`buildingRoom`/逐卡空位过滤、
  落牌 `placementProblem`、拖拽影子（4×3 的长方形占位 + 同一模型影子）、
  `place()`/`cellFree()` 的 spec 都按 `BUILDING_SPECS[kind]` 读；
- 黄区检查遍历 **4 列**（4×3 更容易压到黄区，判据不能只查 3 列）；
- `ARENA_MODELS` / `ARENA_FLAGS` / `labelOf` / `cardIcons` 都要注册新楼。

## D. 待用户看完实机再拍的点

1. 民兵「每人 0.5 面包」是容器口径的折中；也可以改成「民兵完全不吃面包」，
   但那会冲垮「盖磨坊」这条主线，我不建议；
2. 齿轮工厂是否要「生产」点什么（现在只是**被动解锁**科技 + 装饰齿轮）；
3. AI 是否主动把工厂列进建造愿望（本轮**不主动**，手牌里抽到才会盖，
   避免 24 局平衡被前置系统大幅改写）；
4. 4×3 在竖屏窄场地会不会显得挤（实机看）。
