### 2. 根据的读数（都是今天现量，不是从文档抄的）

- 生成器不是程序化几何，**全程没有三角函数**：`grep -E "Math\.(sin|cos|atan|hypot|pow)" app.js` → **0 命中**
  （第一种姿势 `grep -c` 返 0 会以退出码 1 掐断命令串，所以换 `grep -n … | wc -l` 又数了一遍，同样 0）。
- 管线核心就一个函数：`app.js:729 Canvas.blitAll(ctx, frame, animName)` = 三次 `drawImage` + `app.js:750 recolor()`。
  偏移公式（`app.js:732-745`）：base 用 `-getAnimX0(anim,frame)*w` 横向取帧、`-State.base*h` 纵向选体型；
  head/face 用 `-index*w` 选件、`Conf.getOy(part, anim, frame)` 做逐帧上下浮动。
- 一格 **16×24**（`app.js:713-714`、`conf.json w:16 h:24 version:3`）。
- 资产实测尺寸：`base.png 11248×24 → 703 帧 × 1 个体型`；`heads.png 5328×24 → 333 个头`；
  `faces.png 1648×24 → 103 张脸`。`Parts.els.{base,head,face}.max` 运行时读到 **0 / 332 / 102** ✓ 对得上。
  ⇒ 这个移植包**只有一个体型骨架**（代码里被注释掉的体型上限 15/32/53/77 是原版 human/animal/monster 的分段行，本包没带）。
- 我要用的 5 个动画，列号与循环长度（`app.js:83-87` + `app.js:220-224`）：
  `base_stand` 起 0 长 1 ｜ `base_idle` 起 2 长 4 ｜ `base_run` 起 7 长 4 ｜ `base_hurt` 起 12 长 4 ｜ `base_die` 起 17 长 4。
  注意 idle 占 2–6 但 modF 是 `%4`，**第 6 列是不用的余量**，别按间隙长度当帧数。
- 调色板语义（直接读的 `app.js:772-825`）：源色 `skin 绿→Pal.all.body`、`eyes 红→Pal.all.eyes`、
  `suit 蓝→Pal.all.suit`、`item 品红→Pal.all.item`、`more 青→Pal.all.more`；`outline 黄→conf.outlineColor`；
  四个 `*2` 阴影变体 = 同色 × `shadowMod`（conf 里四个都是 **0.5**）再 `parseInt`。
- **UI 变量名是反的**：`app.js:617-618` `palBody = Pal("eyes")`、`palEyes = Pal("body")`。
  我做了实验定性：把 `Pal.all.body` 改成纯红，皮肤色 `238,181,81` **消失**、眼睛蓝**还在** ⇒ `conf.pals.body` = 皮肤色 ✓。
  另：`conf.saved_state` 里的 `palBodyActive=#eeb551` 与运行时 `Pal.all.body` 现值 `#d9a6a6` **不一致**，
  ⇒ `saved_state` 只能当"上次谁选了哪件"的存档，**不能当调色板语义的依据**。
- 一帧实测 14 种输出色；其中 `?`（不匹配任何魔术色的像素）4–14 个 —— 这些**原样保留**，不参与换色。
- **没有 facing 参数**：全代码只有一处 `scale(-1,1)` 的 CSS 镜像（`app.js:3972`，气泡彩蛋）。
  ⇒ 素材都是侧视；左右只能镜像，做不出 8 向。
- **不可播种**：`Math.random()` 满天飞（`app.js:80,1629,4570…`），没有 seed 概念。
  ⇒ 我自己用项目里现成的 `Random`（`src/engine/math/Random.ts`）驱动 index 与颜色，**不造第二个随机数发生器**。
- 经济那侧今天已锁死的口径（要直接复用，不许改）：`每秒趟数 = speed ÷ max(1, 2×格数)`、`每趟 perTrip`；
  矿井 speed 1.2 / perTrip 2，精炼厂 3.2 / 2.2；实测 3 格外矿井 = 0.4/s、精炼厂 = 1.173/s。
- 授权实读：`LICENSE` 头部是 **GNU AFFERO GENERAL PUBLIC LICENSE v3**；
  `README.md`/`manifest.toml` 只说这是 kingbell.itch.io/pixel-sprite-mixer 的 webxdc 移植，
  `source_code_url = github.com/ArcaneCircle/pixeldudes-maker`。**素材（PNG/conf）自身的授权条款仓库里没有**。

### 4. 怎么证明没改答案

- 跑法：改动前 `npx vitest run` 记一次（现在 **94 条全绿**），改动后必须仍 **94 条全绿且不删不改任何一条断言**；
  新增的锁只加在 `tests/dudes.test.ts` 里。
- 口径同一性用一条**等值锁**证明，而不是靠"看起来对"：
  `crystalPerTrip ÷ tripSeconds(楼, 矿) == world.yieldOf(楼).crystal`（同 seed 同布局），
  也就是"画面里的脚程"和"账上的脚程"必须是同一个数派出来的两面；把 `2×格数` 写成 `1×格数` 这条必须打红。
- 每条新锁都先想好怎么打红（写不出打红方式的，就不写那条锁）：
  - recolor 锁：把阴影分支从 `×0.5` 改成 `×1` → 红；把 `skin2` 分支删掉 → 红；把容差 ±1 放宽到 ±60 → 红
    （因为 `eyes 红(255,0,0)` 与 `item 品红(255,0,255)` 只差一个通道，容差一大就互相吞）。
  - 风格确定性锁：`new Random(seed)` 两次 `randomStyle` 必须逐字段相等；把 head 上界写死成 163（原代码那个数）
    而不是读到的 332 → 越界断言红。
  - 帧表锁：`startCol + frames ≤ 703` 且 5 个动画列号/长度等于上面那 5 个读数；把 run 起始改成 6 → 红。
  - 资产锁：`conf.w/h` 与 PNG 实际宽高、`heads/16-1` 与 `maxima.head` 互相对得上；把 w 改成 17 → 红。

### 4. 怎么证明没改答案

- 改动前现量基线再抄进本表（**不再犯 P-001 那个错**）：见下方"开工前基线"。

  2) 小队规模恒定：兵营存活+储备之和永远 ≤ squad；死 1 个 → 储备>0 时立刻回到 squad。
  3) 读条只改一个数：`trainSeconds` 走完 = 多 1 个兵；把 `progress` 累加写成 dt 的两倍 → 锁红。

## P-003 兵营的集合旗（用户 2026-10-20 的原话：点兵营 → 旗子弹出 → 点旗子收进卡包 → 点卡包 → 点别处放下）

### 1. 打算改什么

- 一栋产兵的楼有**一个集合点** `rally`。没动过就是楼中心；放下去之后指到别处。
- 旗子本身是**头顶的一个按钮**（DOM，不是 3D 件）：选中兵营类楼才出现，钉在集合点上方。
- 三步手势全用"点按"，不用悬停、不用长按（竖屏触屏靠得住的那套）：
  点旗子 → 旗子进**旗子袋**（坞上多一格）；点旗子袋 → 进入"等一次落点"的状态；
  点地面 → 集合点挪到那格，旗子跟着挪。手里一次只握一面；Esc 先退出落点状态，再退出就把旗子放回原位。
- 新文件：`src/game/systems/FlagPocket.ts`（纯状态机，node 里能测）、`src/ui/RallyFlag.ts`（旗子那颗按钮）。
- 改动文件：`config.ts`（新增 `isStandable`）、`GameWorld.ts`（`Building.rally` + `setRally` + 事件）、
  `GameApp.ts`（三个对外动词 + handleTap 分流）、`ActionDock.ts`（旗子袋那一格）、`Hud.ts`（每帧投影 + Esc 优先级）、
  `layout.css`（旗子样式与 pointer-events 分区）。

### 2. 根据的读数

- 产兵的楼现在恰好 4 栋（本轮 `squadBuildings().length === 4` 那条锁现量到的）。
- 地面可站性：现有 `TERRAIN` 表里 `buildable` 已经区分了水/岩，采矿那一套 `VEIN_WORK.reach` 用的是
  "占地边缘到矿点格数"。**集合点要的是"人走得过去"，和"能不能盖楼"不是一件事**（水不能站、晶脉能站），
  所以新写一个 `isStandable()`，不复用 `buildable`，也别把两者硬并成一个。
- 投影已有现成件：`GameApp.screenOfWorld / screenOfBuilding`（P-001 的气泡就在用），旗子沿用，不另写一份投影。

### 3. 会动到哪一面

- **会改答案面**：多了一个玩家可改的状态 `rally`（战斗上线后它决定兵往哪走）。本轮它**不参与任何产出计算**，
  所以经济/人口/产量那三组读数一个字不该变 —— 这正是"没改答案"的证据来源。
- **只有时间**：每帧多一个 DOM 投影（和气泡同一条 `positionBubble` 循环，本来就每帧在算）。
- **崩了丢多少**：rally 挂在 Building 上、不写盘，重开即回。旗子袋状态在内存，刷新即清。

## P-004 界面复古化：噪声木纹 + 像素化 + 镀金按键（用户 2026-10-20 指定）

用户原话拆成的判据：面板要**木质**，颜色走"黑黄木色 / 深黑 / 深褐 / 深木色 / 深黄"这一族，
用**噪声**处理，再加**像素化**；其余**按键要镀金感**；整体是复古中世纪。

### 1. 打算改什么

- 新 `src/ui/theme.ts`：`woodPixels()` / `giltPixels()` 是**纯函数**，输出一张能无缝平铺的小图 RGBA；
  `installTheme()` 才碰 canvas 与 DOM，把图变成 data URL 写进 `:root` 的 CSS 变量。
  分开写是为了"噪声对不对"能在 node 里直接断言，不用开浏览器。
- 平铺噪声**不复用 `engine/math/Noise.ts` 的 fbm**：那份的格点是无限散列，边缘接不上，
  平铺会看见一条缝。这里用"格点序号取模"的周期版值噪声（同一个 hash 形状，多一个 period）。
  两者语义不同，不硬并。
- 木纹三层叠加：低频大弯（warp）→ 沿 x 拉伸的条纹（横向板纹）→ 细颗粒，再加**板缝**（每 16px 压暗一格）。
  最后把连续亮度**量化成 6 档**，小图（48px）放大两倍配 `image-rendering: pixelated` —— 像素感来自这两条，不是滤镜。
- 按键镀金：`giltPixels()` 生成的细拉丝金叠在既有 gold token 的渐变上；面板边框改成"雕刻框"
  （外深内浅两道 + 一条金发丝线）。
- 色板按用户给的词排成一个 8 档斜坡（深黑 #120b06 → 深黄 #c8952f），**写死在 theme.ts 里当数据**，
  CSS 不再出现新的十六进制。

### 2. 根据的读数

- 现有 token 里已经有一套 gold（`--gold #d9b25c` / `--gold-hi #f6dc9c`），镀金就用它当地基色，不另起一色。
- 面板现在是 `rgba(16,22,36,.78)` 的蓝黑玻璃 —— 和"木"完全相反，所以 `--panel*` 三条要换掉，
  换完 `.bubble::after` 那个小三角的颜色也要跟着走（它引用 `--panel-solid`，是同一处派生，不用另改）。

### 3. 会动到哪一面

- **只有外观**：不动任何数值、事件、状态。经济/人口/战斗/旗子那些锁一条不该碰。
- **只有时间**：启动时多生成两张小图（48×48 与 64×8），实测入账（预期个位数毫秒）。
- **崩了丢多少**：纹理是启动时现算的，不写盘；生成失败就退回纯渐变（CSS 变量默认 `none`），画面不会白屏。

### 4. 怎么证明没改答案 / 每条怎么打红

- 基线现量：**Test Files 12 / Tests 160**（本轮开工前 `npx vitest run` 的实际读数，见下方回填）。
- 新锁 `tests/theme.test.ts`：色板严格单调、量化后恰好 N 档、**周期平铺无缝**（第 0 列 == 周期外那一列的邻接关系）、
  同 seed 字节全等、换 seed 必有差、板缝行确实比相邻行暗。
  每条都想好了打红姿势：把 period 写成 0/把 quantize 的 step 数改成 1/把 hash 的 y 分量去掉 —— 三发。
- 外观这件事本身没有"答案"可证，所以我只报两个可测的数：**生成耗时**与**像素档数**，
  观感交给他看实拍与可调节的对比页，不在这里替他下结论。

### 5. 风险与代价

1. `image-rendering: pixelated` 对 background-image 各浏览器实现一致度尚可，但 **iOS Safari 早期版本会平滑**；
   兜底是纹理本身就是小图放大，即使被平滑也只是"木纹细腻一点"，不会花屏。
2. data URL 塞进 CSS 变量 = 每张图几 KB 的字符串在内存里，不写盘、不进包，代价只在启动那一下。
3. 深色木 + 金字的**对比度**是最容易翻车的点：正文仍用现有 `--text`，只有标题/按钮字走金色；
   跑完用亮度读数对一次（面板底 vs 文字）确认真的没糊。
4. 字体我也顺手加了"衬线显示体"这一档（只给标题与建筑名），这是我自己加的，不在他的原话里 ——
   做出来单独列出来让他一句话就能否掉。

**两处偏差（如实记）**
1. §4 里我写的"平铺无缝"那条锁，第一版用的是**列均值的接缝 vs 内部中位数** —— 这条锁红过两次而纹理其实没坏：

   换成两把正确的尺子：① `tileNoise` 的周期性（`f(u+1,v)` 与 `f(u,v)` 差 < 1e-6，97 个采样点）；
   ② 逐像素比"接缝列"与"内部列"的平均跳变（实测 3.64 vs 4.15 —— 接缝不是异常值）。
   **打红姿势也验过**：去掉格点取模 → 周期性 291 处不满足 + 接缝 24.07 对阈值 3.25，两条一起红。
2. 我在错误诊断下加过一段"先把坐标折回 [0,1) 再放大"的代码，实测**去掉它一模一样**（周期性本来就靠格点取模拿到），
