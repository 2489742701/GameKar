# P-001 对战模式（Arena）—— 皇室战争那种打法，但"以建筑为主、军队为辅"

用户原话（2026-10-27）：
> 这个模式不好玩……这个素材可以改成《皇室战争》和《部落冲突》的那种玩法……开一个新的文件。
> 对应的素材可以共用，但是逻辑全部不一样，这个主城就是核心。我们给 20 点金。
> 1. 底层随机给 4 张卡牌，也可以配卡组（稍后再做）。
> 2. 先把游戏动起来。双方头上的水晶，一方蓝一方红（对方红）。
> 要增加建筑和旗帜。优先"以建筑为主、以军队为辅"：先建建筑，再建军营；
> 军营自动出兵互相打，也可以直接召唤军队；充分用小像素人生成器做单位、平衡血量。
> 不同于皇室战争：咱们这边的建筑**不会自动掉血掉光**。

## 1. 打算改什么

**新开一个并行模式**，老模式一行不删（`index.html` 仍是抽卡 RTS，`arena.html` 是对战）。
- 新入口 `arena.html` + `src/arena/`（main / config / cards / ArenaWorld / ArenaApp / ArenaHud）
- 复用：`engine/*`（相机/渲染/输入/循环）、`game/models/*`（3D 建筑）、
  `game/dudes/*`（素材包/图集/像素小人/长相）、`ui/theme.ts`（木金材质）、`ui/dom.ts`
- 全新：金币、手牌、双方 AI、出兵与拆核心、旗帜集结点、HUD

## 5. 风险与代价

1. **第三次"重写玩法"**：老模式不是废案，两个入口并存；但用户很可能会只留一个。
   所以我把新模式的逻辑全部隔离在 `src/arena/`，删掉它不影响老模式。
2. **素材复用**：像素小人只有 1 个体型，蓝/红靠"衣服色带"区分（己方蓝带、敌方红带），
   这和 P-002 定的"自己人蓝、敌人随机"不同 —— 新模式要"敌我一眼分清"，所以**强制红带**。
3. **不做配卡组**（用户说稍后），也不做卡牌升级/宝箱/皇冠箱。
4. 旗帜这一层：军营的出兵点可点旗改位置（复用旗子袋那套手势），但一次只做"军营旗"。

### 追加：小人陷进地里 + 一堆 UI 错位（2026-10-27，用户截图反馈）

用户原话：「小人为什么总是只露半边身子，另一半身子陷在地里面……把它自动拉伸一下，拉长一点」
「这个地皮 UI 也有问题，UI 基本上都有问题」。

**根因（代码里量出来的，不是猜）**
1. 小人的脚从 y=0 起算，而草地表面在 y=0.5 —— 整只埋进去 0.49（身高 1.45 的一半还多）。
   老模式的 `UnitView` 一直有 `surfaceY + 身高/2` 这一句，我这一版漏了。
2. 建筑同理：模型说明书写明"局部原点在底面、底面 y=0"，我写成了 `position.set(..., 0, ...)`，
   应该抬到 `footprintSurfaceY`。老模式的 `BuildingView` 也是这么做的。
3. 手牌飘在屏幕正中间：`.ahud` 是 `space-between` 的三段，顶栏/手牌/提示被分别顶到上中下。
4. 桌面宽度下卡片被 `flex:1` 拉成 350px；地图按 45° 斜角转成菱形，四角全是黑洞；
   两颗核心共用同一套模型，只有头顶小水晶分得清。

**修法**
- 小人：`y = 地表 + UNIT_HEIGHT/2`，并把身高从 1.12 提到 **1.45**（等比放大，不拉扁）；没有素材包时的锥体同样抬。
- 建筑：`y = max(占地内各格地表)`。
- HUD：手牌+提示装进 `.ahud__bottom`（`margin-top:auto`），限宽 560 居中，卡面瘦到 62px。
- 相机：对战模式单独一档 `ARENA_CAMERA`，**yaw 0**（正对战场，蓝下红上），
  并按"整幅场地入画"现算缩放（横/竖屏分别算，取大者），竖直多留 4 格给手牌。
  场地四周加一块底盘，不再是黑洞。
- 核心：加一圈阵营色地环（蓝/红），水晶从 0.34 放大到 0.46。

**实测**
- 精灵中心 y = 1.225，身高 1.45 ⇒ 脚在 **0.5**，与草地表面完全一致（修前脚在 0.012，埋掉 0.49）。
- 截图三条（修前/修后）都在这一轮的实机画面里：手牌从屏幕中部移到贴底、地图从菱形变正对、
  双方核心红蓝可辨、单位脚踩地面有影子。

**没做**
- 单位再拉更长（现在 1.45 已经比老模式高 30%）。如果还要更高，改 `src/arena/config.ts` 的 `UNIT_HEIGHT` 一个数即可。

## P-002 横版场地 + 多视角 + 建筑动效（用户 2026-10-27 第二轮）

用户原话要点：横版（左我／右敌）、多视角且能自动移动、射击从塔顶出弹、炮塔转向（**后来更正：
"不是全自动转向"**）、风车要转、卡牌有时点不到、底部 tips 去掉；另外**建筑一律 3×3 占地并放大**、
**建筑要有破损**、**血条要放大**；**田里拖动=移动画布，黑色区域拖动=上下左右转视角**。

### 改动

| 件 | 改成什么样 |
| --- | --- |
| 场地 | 26×16 横版；`midCol=13`，蓝在左、红在右；核心 3×3 落在两端 |
| 占地 | **所有建筑 3×3**；模型统一放大 1.75 倍（`BUILDING_SCALE`） |
| 血条 | 每栋楼都挂（满血隐藏）、宽 2.6、高 0.2；挂在**反向缩放**的子组里，不会被放大 |
| 破损 | 三道深色裂纹，血量 ≤66% / ≤40% / ≤20% 依次露出 |
| 炮塔 | 不是常驻自动转向：只有开火那 0.18 秒里才朝 `aim` 摆过去（用户更正过"不是全自动转向"） |
| 射击 | 塔开火时从**塔顶**生成可见弹丸（箭 0.22s / 炮 0.45s，炮弹走高抛物线），命中仍即时结算 |
| 风车 | 磨坊改成自建件：石塔 + 锥顶 + 四片帆，帆绕 z 轴持续旋转（1.7 rad/s） |
| 视角 | 三个机位（全景 / 两侧对峙 / 跟随战场）+ 自动每 9 秒轮换、镜头缓慢漂到战场质心 |
| 手动 | 玩家一拖就**锁死手动**（不再 6 秒后偷偷抢回），按"视角"按钮才回到自动 |
| 拖动分流 | 起点在**场地内** = 平移；起点在**黑区** = 转视角（左右改 yaw、上下改 pitch，24°–78°） |
| tips | 底部提示整块删掉；换成右上角一颗"视角 · 全景"按钮 |
| 卡牌 | 卡面三块子节点只建一次（以前在 20Hz 刷新里 replaceChildren，手指按下那一帧被换掉 →
  这就是"有时候点不到"）；不再用 `disabled`，点不动时给一句原因 |

### 实测（真页面）

- 风车：`sails.rotation.z` 0.00 → −9.01（0.5 秒）✓ 在转。
- 炮塔：开火窗口里 `turret.rotation.y` −0.60 → −0.57，`aim=0.57`；`shotsMuzzle` 命中 3 帧。
- 弹丸：飞行中 `shotMeshes` 最多 1 个，落点后归零。
- 血条：磨坊 105/300 ⇒ 条可见、宽度 0.35、`y=2.5`（反向缩放生效，不再悬空）。
- 裂纹：0.35 血量 ⇒ 第 1、2 道可见、第 3 道隐藏。
- 拖动分流：黑区 pointerdown → `gestureFromField=false`，场地中心 → `true`；
  黑区拖 120×60 px ⇒ yaw 0 → 26.4°、pitch 52 → 41.2°；田里拖 ⇒ yaw 不变。

### 我自己在这一格犯的两条

1. **血条挂在被放大的组里**：跟着 1.75 倍放大 + 位置抬到 4.2，截图里是两条悬空横线。
   修法是加一层 `ui` 子组做 1/1.75 反向缩放 —— 也提醒我一件事：**位置坐标永远是"局部"的**，
   父级一缩放，所有硬编码的 y 都要跟着重算。
2. **黑区拖动被判成"在田里"**：我一开始只用"射线打到地面平面"当判据，
   但那条射线在场地外也命中（无穷大平面）⇒ 黑区拖动变成了平移。
   改成"命中点落在格子且该格子在地图内"。

### 还没做

## P-003 场地放大 + 中场分隔线 + 金币节奏 + 单位指挥 + 白嫖修正

### 改动

| 项 | 改成什么 | 依据 |
| --- | --- | --- |
| 场地 | 26×16 → **34×20**（`midCol` 17） | 3×3 建筑下 26×16 一栋楼占掉半个半场 |

| 单位指挥 | **点空地 = 全军朝那一点推进**（`ArenaWorld.command()`），到达后自动恢复默认推进；路上遇敌照打 | 用户问"怎么控制单位" |
| 白嫖修正 | 塔的射程改成**从占地边缘量**，和"兵打建筑按边缘算距离"同一口径 | 见下 |

### 白嫖那一格的根因（量出来的）

3×3 之后：兵是"贴到**边缘**"就开始打，塔却是"从**中心**量射程"。
炮塔 4.4 的中心射程只够到边缘外 `4.4 − 1.5 = 2.9` 格，
而弓箭手在边缘外 **3.6** 格就能打到它 —— 差 0.7 格，所以能站着白打整座炮塔。

修法：塔也按边缘量（`range + 半边长`）。修完复测（清掉 AI 的兵，只留 1 塔 + 3 弓手）：

| 场景 | 修前 | 修后 |
| --- | --- | --- |
| 3 弓手 vs 炮塔 | 弓手能站着打，塔掉血（不死的仗） | **弓手全灭**，塔还剩 598/640 |
| 3 弓手 vs 箭塔 | 同上 | **弓手全灭**，塔还剩 436/520 |

### 锁

新增两条：① 点地面 → 全军朝那儿走且到点后清空指令；② 站在塔边缘外 3.5 格的弓手
必须付出代价（掉血或死）。两条都先红过（夹具修正后才绿）：
- 第一条一开始断"塔能放下去"，而我把开局金从 5 提到 8 之后 7 费的炮塔变得买得起，
  旧锁"金不够不能出牌"因此变红 —— 改成先把金压到 2 再试。
- 第二条一开始直接读 `units[0].hp`，而弓手会被打死、数组被清空 → 改成"死了算过、掉血也算过"。

全量 **19 个文件 / 275 条**绿。

## P-004 阵营标识重做：石台 + 会飘的旗 + 模型台面配色

用户否掉了上一版做法："这个炮塔这样很明显是让我不满意的……你让他的那个台面上、
就是你看一下模型上的台面上有颜色，我们额外再准备一个旗帜，然后风车顶盖上的颜色是不同的，
我们再准备一个旗帜，有些地方可以放，比如炮塔上可以放一个飘动的旗帜。"

### 我原来错在哪

第一版是**在脚下贴了一块纯色方板**当地毯用 —— 那不属于模型的一部分，看着像铺了块布。
用户要的是"台面本身有颜色"。

### 现在的做法（新件 `src/arena/props.ts`）

1. **石台**（`makePlinth`）：底层深石（比占地略大）→ 上层阵营色台阶（收进半格）→ 一道亮色沿。
   三层叠起来才像"这栋楼立在一块刻着自己颜色的石台上"。
2. **会飘的旗**（`makeBanner`）：一根杆 + 分 7 段的布。布面每帧按 `sin` 位移顶点
   （两个频率叠加，越靠旗尾摆幅越大），不用着色器。
   - 杆高必须 **高过屋顶**：模型放大 1.75 倍后屋顶约 2.8，杆矮了整面旗都会被楼挡住
     （第一版就是这样，旗子"有但看不见"）。
   - 位置放在石台四角：核心/箭塔左上，磨坊/炮塔/兵营各选一角。
3. **模型台面配色**：磨坊顶盖、炮塔台面按阵营上色（`shade(sideColor, 0.75~0.9)`），
   这样即使不看旗子，也能一眼分出谁是谁的。

### 实测

- 旗子数量：8 栋楼 → 8 面旗（`parts` 里每个都带 `banner`）。
- 布面在摆：同一面旗 t=1.0 与 t=2.0 的顶点数组不同（第 6 个顶点的 z 从 −0.0101 → −0.0123，
  第 9 个从 −0.0095 → +0.0023），确认是**逐顶点**在动，不是整块平面转。
- 炮塔朝向：蓝 `aim=0`、红 `aim=π`（互相瞄准），渲染后 `turret.rotation.y` 分别是 0 / −3.14。

### 一个量具上的教训（我自己的）

验证"布面在摆"时，我用"遍历组里第一个顶点数 >10 的 Mesh"去抓旗面 ——
抓到的其实是**石台的方块**（BoxGeometry 24 个顶点），两次读数完全一样，差点判成"没在动"。
改成按 `geometry.parameters.widthSegments === 7` 抓，才拿到真旗面。
⇒ 抓对象要按**它区别于别的东西的特征**抓，别按"看起来差不多"的尺寸。

### 追加：随机碎裂（废墟长得不一样 + 塔受伤掉渣）

- 新 `src/arena/ruins.ts`：**递归二分切块（BSP）** —— 从占地矩形开始，每次挑一块最大的、
  随机挑轴（长边 72% 沿长边切）、随机比例（32%–68%）切一刀，递归到够块数。
  切出来的块互不重叠、拼起来正好覆盖原地，所以像"这栋楼碎成了这些块"。
  - **确定性**：只由 (seed + 楼号) 决定 ⇒ 同一堆废墟刷新前后一样，不同楼必然不同。
  - `fracture(cols, rows, seed, n)` 给废墟；`spall(...)` 把其中几块推到墙外、压小，给"掉渣"用。
- 废墟渲染：每块按来源（屋瓦 / 墙体 / 木梁）取不同色族，随机转向、随机高度、随机明度；
  出现后前 0.5 秒"从中心炸开再落定"，之后静止，14 秒到期淡出。
- 塔楼破损：每栋楼墙脚埋 5 块碎渣，血量 ≤60% 露一半、≤30% 全露（和原来的裂纹叠加）。

### P-006 追加：跑动动画去抖 + 屏幕朝向 + 外墙碎成面片（2026-10-27 04:00）

用户原话：「人物移动的时候动画感觉设计得不太对劲，会一闪一闪的……让它强制保持大于某个播放顺序」；
「向左向右要依靠这个视野来判断」；「手动重新做一个破损版的模型……随机部分面片碎裂并且掉下来，
露出里面的骨架」。

**① 跑步动画闪**：逻辑是 20Hz、渲染是 60Hz，`moved` 按"这一渲染帧挪了多少"算，
三次里有两次是 0，动画就在 run/idle 之间每帧切一次。移植老模式 `UnitView` 的 **0.18 秒迟滞**
（`runHold`：这一帧动过就续 0.18 秒）。实测 800ms / 49 帧采样：在走的兵从头到尾都是 `run`，
只有"开火→待命"这种真状态变化才切（一次）。

**② 左右朝向**：以前只 `faceCamera(yaw)`，没有翻转。改用现成的 `facingFlip(dx,dz,yaw)` ——
把世界位移投到相机右向量上，镜头转到哪边都不会反着走。顺手修了两个真 bug：
- `entry.x/z` 先更新、再算 `dx/dz`，导致推车的朝向**永远是初始值**；
- 移动火炮的推车小人是"转过向的父组"的子级，`faceCamera(yaw)` 实际世界朝向是 `face + yaw`，
  车往左走时两个小人会背对镜头。现在子级写 `yaw - face`。

**③ 建筑的"碎裂"改成真的掉面片**（这是这一轮的重点）：
- 第一版我做的是"黑色破洞贴纸 + 随机小碎石"—— 用户否了，要**面片本身裂开掉下来、露出骨架**。
- 模型拆成两层：`static`（台基/屋顶/门窗/**骨架**：暗色内衬 + 木柱木梁楼板）+
  `shell`（外墙/塔身切成 0.3 格左右的面片）。视图把面片合成**一张网格**（一栋楼 1 次 draw call）。
- `shell.ts` 的 `WallShell.breach()`：从一块种子板开始，每次摘掉离它最近的一块 ⇒ 洞口连成一片。
  被摘掉的板按原尺寸/颜色/朝向变成落体：重力 16 格/秒²、落地弹一下、速度耗尽后**躺平**。
- 面片数（固定 + 面片）：核心 20+48 / 兵营 16+32 / 箭塔 20+30 / 炮塔 18+12 / 磨坊 19+40。
  面片有轻微色差（±7%），远看是一块块砌的；墙皮掉了以后能看见木骨架和暗色内衬。

实测（真页面）：核心 580/1200 时正面/侧面各缺一片，骨架可见；碎板躺在墙脚（y=0.58，全部 rest）；
兵营拆掉时外墙网格正确释放、无控制台报错。**307 条锁全绿**（`tests/damage.test.ts` 7 条：
崩 n 块网格少 n 块 / 洞口直径 <1.3 / 同种子同位置 / 面片掉光不崩 / 档位单调）。
