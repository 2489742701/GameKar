# P-005 ~ P-009 面包 · 岗位 · 三塔 · 回合 · 弹丸特效（2026-10-20 第二批需求）

用户原话拆成的判据（逐条对上，别漏）：

1. 新增**磨坊**与**田地**；**田地只能贴着磨坊盖**。
2. **磨坊产面包**；**主城默认给一些面包**。
3. **一栋小房屋要 1 个面包**，**一栋小房屋 +4 人口**。
4. **面包不够 → 提示"房屋造不出来"**。
5. **人口不够 → 给提示，但塔楼照样能造**；塔顶冒**人口小头像 + 打叉**；
   **缺员的建筑不能攻击，兵营同理**（不产兵）。
6. 三座塔：**箭塔 / 炮塔 / 魔法塔**，**装填速度与伤害各不相同**，**都有弹药设计**；
   魔法塔**速度特别快、伤害低、要 2 人口**；塔楼**能升级**，**魔法塔升级最贵**，**升级不占抽卡**。
7. 点塔 → 头顶弹**「升级」「拆除」**；**拆除要二级确认**。
8. **箭塔弹药 = 2D 的箭**；**炮塔弹药 = 3D 黑色方块**，落地**爆炸**；开火有**火焰感** + **像素风烟雾**。
9. **水晶获取、人口计算、其他结算都按回合**：敌人进攻 = 回合开始，进攻完 = 回合结束 → **财富自动入账**；
   下一回合有**准备时间**，**准备时间内水晶不涨**。
10. **面包与人口是"容积"不是每回合增加**：战斗中房屋被大量摧毁 → 人口掉到不够驱动兵营，
    但**本回合兵营照常产兵**（回合没结束、没结算）；**结算之后**人口才掉下去，玩家必须抽到房屋才补得回来。

## P-005 面包资源 + 田地 + 磨坊 + 房屋吃面包

**改什么**：`config.ts` 加 `bread` 资源与 `BREAD` 常量；`buildings.ts` 加 `mill`/`field`、
民居 `populationCap: 3 → 4`、民居 `cost.bread: 1`；`cards.ts` 补两张卡（磨坊 rare / 田地 common）；
`GameWorld` 加面包容积与"田地贴磨坊"的邻接判定。

**根据的读数**：民居现在 `populationCap: 3`、`cost.gold: 45`；`inspectPlacement` 的闸门顺序是
边界→地形→占用→唯一→许可→成本→人口（本轮要把最后一条挪走，见 P-006）。

**会动到哪一面**：会改答案 —— 民居人口上限 3→4 是**他指定的**；`data.test.ts` 里若钉着 3 要改口（列在下面"必须改的旧锁"）。

**怎么证明**：田地离开磨坊就盖不下去（新 BuildBlock `no-mill-adjacent`）；面包 0 时盖民居必被挡且提示含"面包"；
磨坊邻 0/1/3 块田地 → 每回合面包 1/2/4。

**风险**：面包进 `cost` 之后，"资源不够"这一句要能报出**缺的是面包**，否则玩家不知道去哪补 → 改 `BLOCK_TEXT.cost` 为逐项列出。

## P-006 人口改成"岗位 + 快照"，缺员不挡建造只挡工作

**改什么**：`BuildingDef.population`（占用）→ `jobs`（需求，不闸门）；
新增回合快照 `approvedPopulation`；`staffing()` 按建造顺序（id 升序，与矿脉分配同口径）依次满足 jobs，
排不到的楼 `understaffed`；缺员的塔不开火、缺员的兵营不产兵；头顶 DOM 徽章"头像 + ✕"。

**会动到哪一面**：**这是本轮最大的一处"改答案"**。以下旧锁必须改口（不是我做砸了，是规则变了）：
- `tests/world.test.ts` 里"人口不足 → 盖不了"那几条：改成"人口不足照样盖得上，但楼缺员"。
- `BLOCK_TEXT.population` 与 `BuildBlock 'population'`：删除。
- `populationUsed()/populationFree()`：语义从"建造闸门"变"岗位需求 vs 快照容量"，函数留着，调用点变。
改口时**逐条在板子里登记改了哪条断言、原来断什么、现在断什么**，不许静默改。

**怎么证明**：同一局里"先盖 5 栋塔（jobs 5）但 approved 只有 3" → 恰好后建的 2 栋 understaffed（按 id 序）；
拆掉一栋民居 → **本回合内** staffing 不变（快照），结算后立刻有 2 栋翻成缺员 —— 这条正是他举的例子，必须有锁。

## P-007 三塔数据 + 弹药 + 升级 + 头顶菜单

**改什么**：`buildings.ts` 加三塔（含 `tower` 规格与 `upgrades` 价目）；`models/buildings.ts` 三个 3D 模型；
新 `src/game/systems/Towers.ts`（索敌→开火→弹丸→装填，缺员直接跳过）；
新 `src/ui/BuildingMenu.ts`（点塔弹「升级 / 拆除」，拆除就地二级确认）。

**升级价目（金币 / 水晶，写死）**：
| 塔 | Lv2 | Lv3 |
| --- | --- | --- |
| 箭塔 | 120 / 0 | 260 / 20 |
| 炮塔 | 200 / 20 | 420 / 60 |
| 魔法塔 | 300 / 60 | 560 / 140 |

**怎么证明**：升级只动 `level` 与派生的 damage/range/reload，**不扣许可、不抽卡**（许可数前后全等）；
Lv3 伤害 = round(基线 × 1.35²)（公式一处）；拆除二级确认前**不许**发生 demolish（负对照：点一次"拆除"后建筑还在）。

## P-008 回合状态机（prep / raid / 结算）

**改什么**：新 `src/game/systems/Rounds.ts`；`GameWorld.tick` 里"每帧 grant 收入"改成**只在结算时按回合累计入账**；
prep 阶段水晶/金币/面包都不涨；raid = 敌人入场到清空；结算 → 入账 + 刷新 `approvedPopulation`/`breadCap` 快照 + 进下一 prep。

**会动到哪一面**：会改答案 —— 现有"每秒进账"的实时读数变成分回合进账（`tests/world.test.ts` 的经济结算那条要改口，登记）。
`incomeRates()` 保留为**速率口径**（HUD 还显示 +1.3/s），只是不再每帧写账 —— 这样气泡/资源栏的读数含义不变。

**怎么证明**：prep 里跑 30 秒，钱包一分不涨；raid 从开始到结束，钱包按 `速率 × 时长` 一次性到账（两臂对照：一臂跑 prep 一臂跑 raid）；
回合号只增不减；结算恰好一次（事件计数）。

## P-009 弹丸与像素特效（箭=2D，炮弹=3D 黑方块 + 爆炸 + 烟雾 + 炮口火）

**改什么**：新 `src/game/fx/PixelFx.ts`（代码生成 4 张极小纹理：箭/烟雾/火焰/爆炸环，`NearestFilter` 硬边）；
新 `src/game/fx/Projectiles.ts`（池化：箭用 Sprite 旋转对准方向，炮弹用黑色 BoxGeometry 走抛物线，命中 → 爆炸环 + 烟雾上升、alpha 阶梯递减）。

**怎么证明**：池上限固定（箭 48 / 弹 24 / 烟 64），超出丢弃并计入读数；弹丸全部回收后 draw call 回到基线（前后各量一次）；
烟雾 alpha 只取 4 个台阶（不平滑）—— 这条是"像素感"的口径锁。

**风险**：特效是这轮最容易把 draw call 打爆的部分；上限先钉死，实测数字回填后再谈要不要加。

### 必须改口的旧锁（逐条登记：原来断什么 → 现在断什么 → 为什么）

### 实测逼出来的两处重排（不是先拍后测）

- **第一版必输**：5 只劫掠兽人 45 秒把议事厅+箭塔+磨坊+田地全拆光（5×9 伤/1.4 秒 ≈ 32 点/秒，建筑总血量 1040）。
  同时金币收入被"准备期什么都不涨"砍到每回合十几块，补不起塔。
  重排：raider 攻 9→6、血 46→40、速 1.25→1.05、间隔 1.4→1.6；建筑血量整族上抬；箭塔 伤 6→8、间隔 0.8→0.7、弹夹 4→6、装填 2.5→2.2；
  prep 45→60 秒；**"准备期不涨"按用户原话收窄成只针对水晶**。
- 重排后复测（两箭塔 + 一田庄、无兵）：第 1、2 回合零掉血，**第 3 回合破防**（第 3 波 9 只）。
  这条曲线是"要玩家真的去补火力/出兵"的形状，先记在这里，下一轮再按更多摆法调。
