# P-012 三档难度：出兵量 + 怪物 AI（用户 2026-10-22：「不调数值，一般来调出兵量，还有怪物的 AI」）

用户原话拆成的判据（逐条对上，别漏）：

1. **目标是"一直撑下去"**：像闯关，靠搭配与资源管理，撑到第几波就是成绩 —— 不存在"设计成第一回合死"。
2. **三档**：简单 = 随机乱出兵、慢慢出、很容易赢；正常 = 正常出兵、要动脑筋；困难 = 比较难。
3. **动的只有两类东西**：出兵量（几只、几波来、什么时候混进远程与石怪、从几处来）与怪物 AI（扑什么、打不打你的兵、散不散、多急）。
4. **不改攻防血造价这些数值**（上一轮的实测摆在那里：单发数值补丁只买到 0~1 回合，属于虚胖）。
5. **他要做的事**：我调完，他实机打一把。所以我这边要能给他一把"现在是什么档、能撑几回合"的预期，别让他拿盲盒试。

## 1. 打算改什么

- `config.ts`：新增 `Difficulty = 'easy' | 'normal' | 'hard'` 与 `DIFFICULTY: Record<Difficulty, RaidProfile>`。
  `RaidProfile` 只装**出兵与 AI**这一类数：每波基数/成长、场上上限、混兵（哪一种、第几回合起、每几只塞一只）、
  分涌（一组几只、组间隔几秒）、来点处数、主城偏好强度、打不打你的兵、散开半径。
  同时**删掉那个没人读的 `ROUNDS.wavesPerRound`**（本轮它变成真旋钮，被 profile 取代）。
- `systems/Combat.ts`：
  - `raidComposition(round)` 改读 profile（现在是写死的 `3 + 2 × round` 与两处混兵阈值）；
  - `spawnWave` 支持"分涌"：一波拆成几组，按间隔在 `update` 里陆续进场（现在是一口气全塞）；
  - 来点从 1 处变成 profile 给的 N 处（按 seed 选、可复现），简单档就是"随机乱出兵"；
  - `objective()` 里写死的 `-2` 主城偏好改成 profile 的 `hallBias`；
  - 敌人新增"打不打你的兵"一条判据（`engageTroops`）：**现状是敌人永远不理你的兵**，
    这条在困难档打开（并把"暗影弓手会先射你的牧师"这句 blurb 变成真的：远程优先奶妈/远程）。
  - 流场缓存从一个全局槽改成"按目标楼分槽"（多来点 + 多目标之后，现在的写法会每帧反复重算）。
- `GameApp.ts` + `prefs.ts` + `world/save.ts`：档位可选、可存、可带进档（版本号 +1，旧档照规矩整份丢掉）。
  `?difficulty=easy|normal|hard` 直接开局；顶栏给一个三档切换（只在"下一波开始"时生效，正在打的这波不换）。
- `ui/DefeatPanel.ts`：判负那句话补上"难度：正常 · 撑到第 7 波"，成绩口径写清。

## 3. 会动到哪一面

- **会改答案**：每波几只、分几涌、从几处来、敌人扑什么 —— 整个防守曲线跟着重排。
  以下旧锁必须改口，逐条登记"原来断什么 → 现在断什么 → 为什么"：
  - `tests/rounds.test.ts` 波次那族：「第 N 波数量 3+2N」「第 2 波起混远程、第 4 波起混石怪」「人数封顶计入 capped」
    → 改成"按档的 profile 算"，并且**默认档 = 正常，正常档的基数先尽量贴现在的 3+2N**，
    好让这几条锁从"数值变了"改成"口径变了"，改动最小。
  - `tests/combat.test.ts` 若有"敌人只拆楼 / 场上敌人数量"这类行为断言，engageTroops 打开时口径会变。
- **只加不改**：难度选择、存档字段、判负面板那一句话。
- **不动的一面**：建筑/兵种/卡牌的攻防血造价**一个都不改**（他点明的红线）。议事厅 600、劫掠兽人 攻 6 血 40 保持原值。
- **崩了丢多少**：改动集中在 Combat 的出兵与选目标 + 一处存档版本号；最坏是某一档来敌节奏错，
  重开一局就干净（档里没有战斗中单位，本来就丢）。

## 5. 风险与代价

1. **分涌 + 多来点 + 多目标**会让现在这份"只有一格流场缓存"的写法每帧反复重算（目标一换就重建 BFS）。
   我按"每栋目标楼一个流场 + 换波时清"来改，并在改前改后各量一次同臂耗时（对照台一臂现在 25~53ms）；
   耗时涨过一倍就如实报数并给取舍，不偷偷加缓存上限。
2. **三档手感只有我自己量过，没被人手玩过**。他要打一把才算验收 —— 所以我把"每档预期撑几回合"
   用实测表写进 README 与判负面板，他打完能直接对上是高了还是低了。
3. **正常档会改波次公式**（哪怕尽量贴 3+2N），牵连回合族旧锁改口；这是规则变更，逐条登记，不静默改。
4. engageTroops 是新行为：困难档一旦让敌人转头咬兵，"兵当肉盾"的摆法会突然变脆。这一档我先做成
   **只对远程生效**（暗影射你的牧师/弓箭手，兽人仍拆楼），幅度可控，也让他那句 blurb 兑现。
5. 本轮**不碰**上一格盘出的另外那些死旋钮与文案漂移（BREAD 那两个、dockMaxHeightPx、5 处 blurb、README 的
   "第 3 回合"矛盾），免得难度这一件事被摊薄；它们留在待办里。

### 必须改口的旧锁（逐条登记：原来断什么 → 现在断什么 → 为什么）

### 我自己定错的目标（如实报）

板子 §2 我写"简单档吃饭流（0 座能还手的楼）≥6 回合"。现量之后这条**做不到，而且不是数没调够**：
