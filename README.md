# GAMEKAR

两个入口，两套玩法，共用一套引擎与素材：

| 入口 | 是什么 | 一句话 |
| --- | --- | --- |
| `/`（index.html） | 抽卡即时战略 | 建筑/经济/人口全靠抽卡，回合制防守 |
| `/arena.html` | **对战**（皇室战争那一路） | 蓝红各一座核心，20 点金，**以建筑为主、军队为辅** |

对战模式见文末「对战模式」一节；它不动老模式的任何逻辑（两边的存档键也不同前缀）。

抽卡驱动的 2.5D 即时战略。建筑、经济、人口**全部**来自抽卡：盖楼要抽、加产出要抽、涨人口上限也要抽，
抽到的建筑卡就是一张"可以盖一次"的建造许可。防守靠塔与兵，进攻按**回合**来。

## 跑起来

```bash
npm install
npm run dev          # http://localhost:5173
npm run check        # 类型检查 + 258 条回归
npm run build        # 产物在 dist/，three 单独分包
```

开发期可以在控制台直接敲：

```js
game.pull(10)                 // 十连，走完整结算
game.build('farm')            // 进入田庄的放置模式
game.place('mine', {col:20,row:18})   // 跳过交互直接落位
game.world.resources          // 金币 / 晶钻 / 面包
game.upgrade(towerId)         // 升级一座塔（不扣许可）
game.stowFlag(barracks)       // 收集合旗 → game.armFlag() → game.dropFlag(cell)
game.prefs.themeId                    // 玩家自己调的界面材质（可分享的码）
game.setDifficulty('easy')    // 换难度（下一波生效）；game.difficulty 读当前
game.combat.raidPlan(3)       // 这一档第 3 波来谁（计划表，不含进场时机）
game.setOrientation('portrait')       // 在桌面窗口里锁定竖屏档位
```

`?seed=20261019` 换一张地图（同一个 seed 永远同一张图，连抽卡序列、小人长相、敌人来点都一样）。
`?difficulty=easy|normal|hard` 直接指定这一局的难度（不给就读本地偏好，再不给就是正常）。

## 画面是怎么回事

- **正交投影**：`OrthographicCamera`，远处建筑不会缩小，格子尺寸全程一致 —— 这是红警/帝国时代那种平铺感的地基。
- **2.5D 俯角**：默认俯角 50°、方位角 45°。看得见屋顶，也看得见立面；`game.camera.setPitch(25)` 会更贴红警。
- **短边锁格子**：相机按"屏幕短边看几格"来定视野，所以横竖屏来回切，建筑不会突然变大变小。
- **一次 draw call 铺完地图**：2116 格分两个 InstancedMesh（陆地 + 水面），树/灌/岩各自合批一个。
  水面和发光晶簇不合批 —— 顶点色走不了 emissive，而晶脉"亮着"本身就是玩法信号。
- 建筑是**程序化建模**：一份"说明书"（`box/prism/plinth/cyl/cone/crystal`）拼出低多边形模型。
  **会动的件**单独标记：`{ spin, pivot }` 让一件东西绕某个轴心自转（现在只有风车帆用它），
  其余件照旧是静物 —— 一个没有 `spin` 的模型，运行时一眼就看出它不会动。
  将来换真实 glTF，只动 `src/game/models/`，玩法和 UI 一行不改。
- 界面材质也是**现算的**：木纹与镀金是启动时用周期噪声生成的小图（见下方"界面是块木头"），
  玩家还能自己调，并给一个可分享的 ID。

分层只有一条规矩：**`engine/` 不许 import `game/`，`game/` 不许 import `ui/`。**
世界层与战斗层都不 import three，也不碰 DOM，所以单测能直接 `new GameWorld(map)` 跑一百抽、打完一整个回合。

## 核心循环

```
抽卡 ──▶ 建筑许可 ──▶ 盖楼 ──▶ 产晶钻 ──┐
   ▲                                  │
   └──── 经济卡（永久 +/s）· 人口卡（上限）◘ 回合结算（财富自动入账）◀┘
```

### 回合：准备 → 接敌 → 结算

- **敌人进攻 = 回合开始，敌人清完（或拖过 90 秒）= 回合结束**，结束时财富一次性自动入账。
- **一波不是一次塞完**：按难度分成几涌，每组几只、组间隔几秒，从一处或几处边缘进来。
  后面还有涌的时候不算"清场"，回合不会在两涌之间提前结算。
- **准备时间（60 秒）内水晶不涨**；金币整回合都在攒，但都压在结算那一刻才进钱包。
- **面包和人口是"容积"，不是每回合增加的产量**：
  战斗中房屋被大量摧毁 → 人口容量当场掉下去，但**本回合兵营照常产兵**（回合没结束、没结算）；
  结算之后容量才生效，玩家必须再抽到民居才补得回来。
  反过来，抽到民居是**立刻**多 4 个人口 —— 快照只往上走，不往下走。

### 三档难度：只动"怎么来敌"，不动攻防血

点顶栏「难度」循环切换（简单→正常→困难），或开局用 `?difficulty=easy|normal|hard`。
**换档下一波才生效** —— 正在打的这波不许中途变节奏，牌上会写成「难度·正常→困难」。
档位也记进存档：接着上一局刷新，还是那一档。

拧的只有两类东西（`config.ts` 的 `DIFFICULTY`，单位表一个数字没动）：

| | 每波几只 | 第 1 波 | 每组几只 / 隔几秒 | 从几处来 | 混兵 | 扑不扑主城 | 急不急 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 简单 | 2 + 0.5×(N-1) | 2 只 | 2 只 / 5 秒 | **3 处**（乱出兵） | 第 8 波起混远程 | 谁近拆谁 | 每打一下停 1.2 秒 |
| 正常 | 4 + 1.2×(N-1) | 4 只 | 4 只 / 4 秒 | 1 处 | 第 3 波远程、第 5 波石怪 | 主城减 2 格 | 不喘 |
| 困难 | 6 + 2×(N-1) | 6 只 | 6 只 / 2 秒 | 2 处 | 第 2 波远程、第 3 波石怪 | 主城减 4 格（宁远也要打心脏） | 不喘，**远程还会转头射你的兵** |

实测（对照台，纯草场、钱管够、同一 seed；读数 = 判负回合，撑过第 20 波记 ≥21）：

| 摆法 | 简单 | 正常 | 困难 |
| --- | --- | --- | --- |
| 1 箭塔 + 田庄 | 9 | 2 | 2 |
| 2 箭塔 + 田庄 | 10 | 3 | 2 |
| 3 箭塔 + 田庄 | 15 | 5 | 3 |
| 2 箭塔 + 炮塔 + 田庄 | 15 | 5 | 4 |
| **2 箭塔 + 兵营 + 田庄** | 10 | **9** | **6** |
| 2 箭塔 + 兵营 + 神龛 + 田庄 | 13 | 9 | 6 |

正常档那一列就是"要动脑筋"的形状：**只堆塔到 5 波，塔 + 兵一步跳到 9 波** ——
火力与人手搭配是有效解，纯堆塔不是。困难档更陡：没兵几乎撑不过 4 波。
简单档则一塔就能舒服过 9 波，用来认路。

### 面包：磨坊 + 田地 + 房屋

```
一栋民居 = 1 个面包 + 4 个人口上限
一座磨坊 = 每回合 1 个面包，四周每贴一块田地再多 1 个
主城     = 每回合白送 2 个面包
```

- **田地只能贴着磨坊盖**（离开磨坊直接判 `no-adjacent`，幽灵是红的）。
- 面包不够时盖不了房屋，提示会**点名缺的是面包**（"盖不了：资源不够（面包 1）"）。
- 面包有容积上限：底子 6，每座磨坊 +6。到顶就不涨，多出来的不是消失，是没进账。

### 人口是岗位，不是闸门

塔楼 1、炮塔与魔法塔各 2、兵营类 4、田地 1、磨坊 2 个人口。
**人口不够时照样能盖**（不然玩家会被卡死在"想补火力但补不了"），代价是那栋楼**缺员**：
塔不开火、兵营不产兵，头顶挂一枚"人口头像 + ✕"的徽章。缺谁按建造顺序排，同 seed 同摆法结果一定。

### 三座塔：伤害、射速、弹夹各不相同

| 塔 | 单发 | 射速 | 弹夹 | 空仓装填 | 射程 | 人口 | 特点 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 箭塔 | 8 | 0.7s | 6 | 2.2s | 7 格 | 1 | 最远，一弹夹打完要喘 |
| 炮塔 | 22 | 1.6s | 2 | 5s | 4.5 格 | 2 | 铁弹落地炸 1.4 格，专治成群 |
| 魔法塔 | 3 | 0.22s | 10 | 3s | 6 格 | 2 | 快得看不清，单发很轻 |

- 弹丸是**有实体的**：箭是 2D 像素箭（跟着飞行方向转），炮弹是 3D 黑色方块走抛物线、落地爆炸 + 一把往上飘的像素烟，
  魔弹是青色光点。**伤害在落地那一刻才发生**，不在开火那一刻。
- 点塔 → 头顶弹「升级 Lv? · 金X 水Y」「拆除」；**拆除要再点一次"确定"才动手**。
- 升级**不占抽卡**，只花金币与水晶，最高 Lv3（每级伤害 ×1.35、射程 +0.6、装填 −10%）。魔法塔每一级都贵过另两塔同级。

### 兵营与集合旗

一栋营固定产一支小队（兵营 3 骑士 / 弓手营 4 弓箭手 / 兽穴 3 兽人 / 神龛 2 牧师）。
死一个先从**储备**里立刻补，储备空了才在头顶走生产读条。兵出营后跟着**集合旗**走，营位就是布防点。

旗子那三步是：**点兵营 → 头顶弹旗 → 点旗子收进"旗子袋" → 点旗子袋 → 点一处地面放下**。
全程只用点按（不靠悬停、不靠长按），一次手里只握一面。

### 采矿是算出来的，不是给的

矿井和精炼厂自己不产晶钻，它们**派小人去附近的晶脉跑运输**：

```
每秒趟数 = 脚程速度 ÷ (2 × 到矿的格数)      每秒产出 = 趟数 × 每趟载重
```

- 矿越远，路上耗得越多，产量越低；**超过 7 格直接不派人，产量为 0**。
- 精炼厂的高产不是凭空加成，而是小人走得快（3.2 格/秒 vs 矿井 1.2），还能同时包 3 个矿点。
- 一条晶脉同一时刻只归一栋楼，免得两栋挤一个矿点白送产量。

### 晶脉上盖楼要过一道确认

默认晶脉不是"不许盖"，而是"盖之前问一次"：**在这里建XX会毁掉 N 格晶脉，毁掉之后这块地方再也采不出东西**。

- 点取消 → 一格都不动，许可也不扣。点确定 → 楼起来，那几格永久变成裸土（拆楼也不变回来）。
- 弹窗下方有"不再提示"，勾了就记在本地（`Prefs`，无痕模式自动退回内存存储）。
- 幽灵三种脸色：绿=随便盖，**琥珀=能盖但会毁矿**，红=盖不了。这个判断和落位用的是同一个函数。

### 屏幕上现在看得见什么

战斗内核里的数早就有了，缺的一直是"露出来"。这一轮补上六样：

| 位置 | 内容 | 什么时候出现 |
| --- | --- | --- |
| 顶栏 | **像素图标 + 数字**：金币 / 晶钻 / 面包（现量/上限）/ 人口（用/可用） | 一直在 |
| 建造托盘 | 造价也是图标 + 数字（不再写"金币 120"那种汉字） | 打开建造托盘 |
| 信息卡 | **战力一行**：剑=单发伤害或兵的攻击、盾=防御、心=兵的血、人=要几个手、面包=每回合底产 | 选中一座楼 |
| 楼头顶 | **血条六格**（剩两格以下翻红） | 掉过血才挂；满血不挂，一屏幕条等于没有信息 |

图标是**代码画出来的 8×8 字符画**（`src/ui/icons.ts`，形状就是一串字符，改形状只改那串），
不用 emoji/字体符号：符号会随系统换字形，而图形必须跟数字对得上。
伤害数只从开火那一处拿（`Combat.towerDamage`），所以卡片上的剑和真正打出去的弹丸不会是两个字。
| 楼头顶 | **生产读条** + 一句 `生产中 40%` / `补 2/3 · 储备 1` / `满编 3/3` | 兵没满编时 |
| 楼头顶 | **弹夹**：`Lv2 · 装填 3.4s` / `Lv1 · 弹夹 5/6` | 塔打空或装填中 |
| 楼头顶 | 人口头像 + ✕ | 排不到人手（缺员的塔不开火、兵营不产兵） |
| 楼头顶 | **锤子 SVG（会抡）** | 工匠**真补到血**的那一帧起；在路上、或已补满都不亮 |
| 来点格上 | `第 3 波 · 从这边来 · 8s`（简单/困难一档多处来敌时写成 `从 3 处来`，标出来的那一处是首要来点） | 准备阶段最后 15 秒 |
| 全屏 | 判负面板：撑过第几回合、还剩几栋楼、场上几只敌人 + 「重开这一局」 | 议事厅被打掉 |

判负那句"还剩几栋楼"**不含议事厅自己**：它是在楼真从账上消失之后才广播的，
早一步统计就会把刚塌的心脏算成"还在"。这条踩过一次，锁在 `tests/readouts.test.ts`。

### 存档落在回合之间

- 盖楼、拆楼、回合结算三个时刻自动写本地；**战场上的兵与弹不存**，
  所以刷新 = 回到上一次结算，正在打的这一波重新来。文案里就这么写，不假装能续战斗。
- 档里带版本号与 seed：**版本不符或 seed 不符就整份丢掉**，不猜、不迁移——
  猜错的存档比没有存档更坏（楼是按格子记的，换张图去盖它们等于凭空造 bug）。
- 读档走 `adopt()`：走盖楼的全部副作用（占地、矿脉计划、事件），但**不扣资源、不扣许可**。
  这条有专门的锁：一个许可都不发的新世界，读档照样把楼摆回来，金币与许可数与源局全等。
- 「重开这一局」先清档再跳同一张图（`?seed=` 带过去），不清的话读档会把已经输掉的那局再端回来。

### 操作

拖 = 平移 ｜ 双指捏合 = 缩放 ｜ 双指转 = 转视角 ｜ 滚轮 = 缩放 ｜
点空地 = 选中那格 ｜ 点楼 = 选中那栋 ｜ **再点同一个目标 = 取消选中** ｜ **长按楼 = 头顶弹气泡说明** ｜
点塔 = 头顶弹升级/拆除 ｜ 点旗子 = 收进袋 ｜ **点顶栏「材质」或按 T = 开调参面板** ｜ Esc = 谁在最上面先收谁。

### 界面是块木头

面板不是渐变糊出来的，是**启动时现算的噪声小图**（`src/ui/theme.ts`）：

- 三层周期值噪声（大弯 → 长横纹 → 细颗粒）+ 每 12 像素一道板缝，亮度**量化成 6 档**；
- 图只有 48×48，按整数倍放大配 `image-rendering: pixelated` ⇒ 放大后看到的是真方块，不是糊；
- 按键走镀金：金色渐变上压一层现算的拉丝纹理，顶边一道镜面高光；面板边框是"外深内浅 + 一条金发丝"的雕刻框。
- 噪声的格点序号**取模**，所以平铺看不见接缝 —— 这条有锁（`tests/theme.test.ts`），
  而且写锁的过程里揪出了实现本身的一个错（y 行混合把 `tx` 写成了 `ty`）。

### 木头可以自己调，还带一个分享码

点顶栏「材质」（或按 `T`）开面板：八条滑杆调**明度 / 色阶档数 / 纹路密度 / 板宽 / 板缝深浅 /
像素块放大 / 木纹变体 / 镀金强度**，另有淡·中·重三档预设与"恢复默认"。

- **改动自动保存**，没有保存按钮；存进本地偏好的**就是那个 ID**，所以不会出现"参数与码对不上"。
- 每次改动同时输出**独有 ID**（如 `mk-11q37sz`）：同一套参数永远同一个码，别人贴回输入框就是同一块木头。
  八个字段量化后 28 bit，base36 六位装得下；前缀里那一位是版本号，**以后加字段必须升版本**。
- 贴回来的码读不出来就**什么都不改**，只提示一句 —— 不让一个错字偷偷换掉玩家的界面。
- 拖动过程中不重算纹理（实测热态重算 4–7ms，冷启动那一次 161ms 含 PNG 编码 warm-up），
  最后一次改动后防抖 220ms 再算，面板底部把耗时显示出来。
  这里故意不做"CSS 滤镜先凑一下"的预览：滤镜下的旧纹理和真纹理不是一套，松手会跳，玩家以为坏了。

| 读数 | 实测 |
| --- | --- |
| 默认长相的码 | `mk-11q37sz`（钉在锁里，偷偷改默认值会红） |
| 热态重算两张纹理 | 4–7ms（木 2 + 金 2） |
| 冷启动第一次生成 | 木 161ms + 金 68ms |
| 500 组随机参数往返 / 2000 组撞号检查 | 全等 / 2000 个互不相同 |

### 小人是拼出来的，不是画的

素材来自 Pixelart Sprite Mixer（来源与授权见 `public/assets/dudes/CREDITS.md`）。它**不是**程序化几何：
全代码零三角函数——一个小人 = 三张贴纸各取一格叠起来，再按"魔术色"整像素换色。

| 事实 | 实测 |
| --- | --- |
| 单帧尺寸 | 16 × 24 像素 |
| 拼装空间 | 333 个头 × 103 张脸 × 5 组调色板各 39 色 |
| 体型 | 本包只有 **1 行**（原版按行分 human 0-15 / animal 16-32 / monster 33-53…） |
| 帧表 | 703 列动画；已量到 21 条动作（近战/弓/法/牧/冲撞/被击飞各有自己的动作） |
| 空列 | 头表 14 个分区的**起始列全是空格子**（0,34,51,63,102,127,150,164,200,210,240,274,306,318）⇒ 取头一律"分区 ∩ 非空列" |
| 蓝带 | suit 调色板 39 色里满足 `B>R+25 且 B>G+15` 的恰好 5 条 ⇒ 自己人从这 5 条里取，敌人随机 |
| 朝向 | **正面素材**（剪影左右对称度 0.917–0.969）⇒ 卡片永远正对相机，不做左右翻面 |
| 可复现 | 上游是 `Math.random` 不可播种 ⇒ 长相改由 `seed + 阵营 + 兵种 + 变体` 派生，取样顺序不影响结果 |

只搬了**算法**（`src/game/dudes/` 全部自己重写，没拷一行上游代码），素材是 4 个原样未改的数据文件。
运输小人站在矿井与晶脉之间来回走，**来回秒数用的就是经济算产量的那条公式**，
所以不会出现"人跑得飞快而产量没变"。上限 48 人，因上限没派出去的任务在左上角显成"排队未派"。

授权两件事分开看：代码我们重写了（上游是 AGPL-3.0）；**素材自身条款仓库里没有**，
对外发布前要确认 itch 页面条款。真要换包，只替换那 4 个文件即可，代码不动。

### 魔法塔：中间掏空，晶核悬在里面

原来是实心塔身 + 顶上蹲一颗晶核（总高 1.84）。现在上下两段，**中间用四根柱子撑开**，
晶核悬在空腔正中、绕自己慢慢转；顶上补檐口 + 小塔身 + 蓝顶，总高 **2.88**（三塔里最高）。

晶核离下段楼板 **0.14**、离上段檐口 **0.14**，谁都不碰 —— 这是设计上就该悬着的件，
所以模型里给它挂了 `float: true`，几何锁看见这个标记放行。**写这个标记之前先问一句"这是故意的吗"**：
它不是"漏接了东西"的免死金牌。

#### 顺带挖出来的：`crystal` 的 h 原来是半高

`makeCrystal` 拿八面体（Y 半径 = radius）直接 `scale(1, height / radius, 1)`，
得到的是 **±height**，总高是 2×height。于是"高 0.52 的晶核"实际纵向 1.04，
**把魔法塔的楼板和檐口一起插穿** —— 而几何锁当时看着它"被楼板托住"，一切正常。

现在按文档里写的口径修成"h = 总高"，六个调用点的高度全部翻倍保持外观不变。
被这颗雷埋掉的两处顺带露出来了：神龛和瞭望塔的顶芯原本整个埋在屋顶里（屏幕上根本看不见），
现在各自坐在锥顶尖上。

> 这条也是"锁要靠反证"的又一次证明：第一次做反证时把 `float` 删掉，锁**没红** ——
> 因为晶核同时带 `spin`，被"自转件"那条豁免先吞掉了。把自转豁免收紧成
> "轴心必须插在别的件里"之后，删掉 `float` 才真的会红。

### 旗子是真布，不是一根尖顶

原来兵营杆顶扣着一个**红色圆锥** —— 所以"只有旗杆没有旗帜"这句话是对的：那玩意儿既当尖顶又当旗。

- 杆顶改成**平头**（不做尖顶/宝顶）；
- 旗面是新的 `flag` 原语：`PlaneGeometry(w, h, 10, 5)`，锚点挪到**左上角**（贴杆那头），
  挂在杆顶、自由端朝外；
- 顶点在着色器里按 `uv.x`（0 = 贴杆，1 = 自由端）叠两道不同频率的正弦，
  振幅乘 `uv.x²` —— 贴杆那头几乎不动，自由端甩得最狠，看着才是布不是纸板；
- 旗子**不投阴影**：阴影贴图那一遍不跑顶点位移，投出来是一块硬纸板影子。

| 读数 | 实测 |
| --- | --- |
| 摆动 | 0.075 + 0.04 两道正弦，周期约 1.5 秒 |
| 验证 | 定格 24 帧（0.09 秒一帧），旗面区域两帧间 475 个像素变化 |
| 代价 | 每个旗面 1 个 mesh + 1 份材质（同色共享），全场只更新一个 uniform |

#### 两个只有截图才看得出来的错

第一版拍出来被用户当场指出"风向不一样、还穿模"，两条都是真的：

- **风向反了**：左旗用 `rot: [0, π, 0]` 翻面 —— 绕 Y 旋转会把局部 +Z 翻到世界 −Z，
  两旗的抖动相位正好相反。改成**镜像几何**（`part.dir = -1`），只翻 X 不碰 Z，才是同一阵风。
  现在有一条锁钉住它：旗面**不许绕 Y 转**，而且同一栋楼的旗子 `dir` 必须一致（把旋转改回去，锁会红）。
- **杆底悬着**：杆子挪到屋外 0.22 格的位置，那里的屋面只有 **1.24**，可杆底是按"正脊高度 1.38"写的 ——
  悬了 0.14，布的下沿又正好咬在屋顶的山墙轮廓上，屏幕上就像"布插进屋顶"。
  现在杆高 0.87、杆底从 1.20 起，埋进坡面 0.04。

几何锁也为它开了第三类例外：`hang`（靠上沿挂住）。这条**不是"有标记就放行"** ——
必须真的找到一个顶边与它齐平（±0.1）且水平压着的件，才认。

### 小人会转身了（贴图镜像）

素材默认朝右，往**屏幕左**走要镜像。统一入口一个：

```ts
facingFlip(dx, dz, yawDeg, previous, deadzone = 0.012)  // 世界位移 → 要不要镜像
```

三个坑都写在这一个函数里了：

- **必须投影到相机的右向量上**（`dx·cosθ − dz·sinθ`）。直接看 `dx` 的符号，相机转 180° 之后就反了 ——
  小人会"往左走朝右看"；
- **死区 0.012**：纯上下走（横向几乎不动）时保持上次朝向，不然每帧抖一下；
- 镜像走的是**贴图 UV**（`frameUv` 把 u 两头对调），不是翻 mesh —— 翻 mesh 还得连带处理法线、双面与影子。

矿工和士兵都从 `DudeSprite.setFlipX()` 这一个口子进，没有第二套实现。

> 先量后改：run 帧的 alpha 质心只偏左 **0.92px / 16px**（≈6%），剪影接近对称，
> 所以镜像的收益是"看着顺"，不是"看着对"。这个数是逐帧统计出来的，不是拍脑袋 ——
> 原来文件头那句"这批素材是正面所以不翻面"就是没量过的结论。

| 读数 | 实测（相机 yaw 45°，连续 255 个移动帧） |
| --- | --- |
| 往屏幕左走 → 镜像 | 135 帧，全部镜像 |
| 往屏幕右走 → 不镜像 | 115 帧，全部不镜像 |
| 掉头瞬间 | 2 帧保持原朝向（死区），占 0.8% |

### 收支一律写成带符号的数

用户原话："不需要'住四个人吃一个面包'这种的，就是按'人口加 4，面包减 1'这种方式来。"

于是把战力条（`powerOf`）改成**从 def 现算的带符号收支**，手写的数字从文案里全部拿掉：

| 位置 | 原来 | 现在 |
| --- | --- | --- |
| 民居 blurb | `住 4 人，吃 1 面包。` | `人口的地基：盖得越多，能派出去的人越多。` |

### 这一轮的五件事

**1. 矿工不再"来回抽"**：一段行程里**走 55%、停 45%**（矿点边上停一次、楼门口停一次）。
关键是**总周期不变**（还是经济公式算的 `trip`），所以"看见的忙碌"和"账上的产量"仍然同步。
实测：9 秒内静止帧占 **41.6%**（按构造应是 45%，差的是掉头那几帧）。

**2. 箭走抛物线**：原来箭几乎是平飞（弧高 0.12），现在**按距离抬** —— `min(0.95, 0.12 + 距离×0.11)`。
近距离还是平推，远射才抛起来。实测同一发箭：t=0.17→0.26、t=0.51→**0.50**、t=0.69→0.41。

**3. 议事厅没有拆除按钮**：`unique` 建筑干脆不渲染那颗按钮 —— 拆了就没有家，这一局没法玩。

**4. 建造/拆除同一格**：`建造` → 托盘打开 → 再点一次 **变成"拆除"** → 点一栋楼（格子显示"拆除 · 民居"）
→ 再点一次执行。和放建筑同构，都是"先按进入、再按执行"。
实测：两次点按后 `demolishMode=true`、选楼后标签是"拆除 · 民居"、第三下 `demolished=true`。

**5. 议事厅的工匠**：议事厅自动产出 **2 个工匠**（死了隔 8 秒补），行为是
"眼前有敌人就抡一锤，没有就去补最惨的那栋楼"，每秒补 5 血。
实测：民居被打到 80/200，11 秒后回到 **162**。

> 工匠踩过的坑：一开始把他们算进敌人的"猎物表"，结果一波兵进城就围着两个修墙的抡，
> 楼一点血都不掉 —— 难度表那套"先拆近的 / 直奔主城"的偏置被两个杂役废掉了
> （`rounds.test` 的波次偏置当场红）。现在他们是**非猎物**。

**6. 矿工也会还手**：1.5 格内有敌人就停下挥镐，1.4 秒一下、3 点伤害，
伤害走 `combat.strike()`（跟塔/兵同一个公式）。这是**临时办法** ——
矿工不是战斗层的单位，等把他们单位化之后这两个接口就该删。

### 弹夹画成一发一个方块

原来是一条连续进度条：6 发的弹夹只显示成"一条 66% 的条"，看不出还剩几发、也看不出装到第几发。
现在**一发一个方块**，装填时逐格点亮。

实测（箭塔，6 发）：

```
111110 → 111100 → 111000 → 110000 → 100000 → 000000   (开火)
000000 → 100000 → 111000 → 111100 → 111110            (装填)
```

方块数跟着 `magazine` 走（箭塔 6、炮塔 3…），容量变了才重建；
装填进度由 `combat.reloadSeconds(b)` 给的总时长算（含等级缩放），没有总时长就只能画"满格跳变"。

### 工匠改成"有伤才出门"

第一版是常驻两个 —— 玩家看到两个不干活的小人杵在议事厅门口，第一反应是
**"怎么又多了两个守卫"**。现在：

- 没有楼掉血 → 工匠安静待在议事厅里（名单里没有他们）；
- 有楼掉血 → 出门，去补最惨的那栋；
- 全部修满 → 自己走回议事厅，**走到门口才从名单里摘掉**（不是凭空消失）。

实测：无伤 0 人 → 受伤 2 人 → 修满后 **6.2 秒**回屋归零。

### 两个"看起来不对"的修正

**1. 矿工瞬移 —— 是我上一轮写错的**

"走一段停一段"那段，回程用了 `leg = (1 - u) * 2` 再配 `s = 1 - legT`，
等于**在 u=0.5（去程结束那一刻）把 s 从 1 直接翻成 0** —— 矿工在矿点原地瞬移回楼门口。

现在回程是 `leg = (u - 0.5) * 2`（这一段从起点算），s 在 u=0.5 处两边都是 1，连续。
验证方式不是看截图：**按每帧真实 dt 算瞬时速度**，14 秒内没有一帧超过 12 格/秒（最高 3.91），
瞬移会是一条 4 格/帧的尖峰。

顺带把 `WALK_SHARE` 从 0.55 放宽到 0.65：0.55 时走路被压缩成 1.8 倍速（5.5 格/秒），
看着还是"蹭蹭蹭"。现在 3.91 格/秒，停顿仍占 35%。

**2. 工匠默认应该在议事厅里**

上一版让他们"走回门口再收起来"—— 结果没活的时候，两个小人就在议事厅外面漂着，
玩家第一反应是"他们怎么跑出来了"。现在**没伤就等于不在场上**（直接从名单里摘掉），
出门只是"有楼掉血"这一件事的副作用。

实测：无伤 0 人 → 打伤一栋 2 人 → 修满 **立刻** 0 人。

### 工匠的进出与走路（重写）

玩家反馈三条，全中：

1. **"他没有自动回去，而是自动收进建筑里面"** —— 上一版没活时**原地摘掉**，看着像被吞了。
   现在有固定的**门口格**（`doorCell`：占地外圈、正 +Z 那面第一格能站的），
   出门从这里出来，修完**走回这一格才消失**。
2. **"走路一卡一卡的"** —— 原来只会直线朝目标撞，撞到水/石头时 `move()` 沿轴滑，屏幕上就是抽搐。
   现在接上了和矿工同一份 A*（`walk.ts`），沿折线走。
3. **"他们也不修建筑，就卡在那里"** —— 真 bug：`const job = this.workerJobs.get(id) ?? {...}`
   **新建的对象没写回 Map**，于是每帧都从零开始，`idx` 永远是 0、`followPath` 每帧都判定
   "已经到了第一个路点"却推进不了 —— 人站在门口一动不动，一次也没修。

实测（民居被打掉 150 血）：工匠从议事厅门口出发 → 走到民居门口 → 血量 50→120（持续上涨）→
修满后距离议事厅 5.4 → 4.9 → … → 1.7 一格一格走回去，**到门口那格才消失**。

### 动画"打架"、空闲补弹、头顶只留方块

**1. 动画抽搐 = 每帧在抢状态**

`animOf` 用 `moved > 0.004` 判跑步。可单位站着时会被 `separateUnits` 推一两毫米，
这个判断就在真/假之间反复跳 —— `run` 和 `idle` 每帧切一次，屏幕上就是抽搐。
现在加 **0.18 秒迟滞**（动过就续命，停了才慢慢放掉）。
实测：120 帧里只切了 **1 次**（run → idle）。

**2. 空闲补弹**

原来只有"打空才装"：一座打了一半的塔（3/6）在没敌人的时候会一直停在 3/6，
要等下一波怪来了才看见它重新开火 —— 读起来就是"等怪物来才装填"。
现在**没目标且弹夹不满就慢慢补满**（有目标时不补，免得耽误输出）。
方块也跟着从"现有几发"往上填，不是从 0 重画。

实测：打完剩 1/6、敌人撤走后 → `reload 1.9→0.2`，方块 `100000→110000→111000→111100→111110` → 6/6。

**3. 头顶弹夹只留方块**

去掉"Lv1 · 弹夹 5/6"那串字 —— 一列方块已经说清"还剩几发、在不在装"，
等级和余量在选中卡片里有完整一行。

**4. 工匠换目标加粘性**

两栋楼伤得差不多时，每帧重新选"最惨的那栋"会来回横跳、路径每帧重算，人原地打转。
现在只有当前目标修好了、或者新目标明显更惨（差 15% 以上）才换。

### 旗架：旗子袋点开就是一排旗子卡

原来的收旗要三步：点楼上的旗 → 点旗子袋 → 点地面。中间那步"点旗子袋"以前只会检查
"袋里有没有旗"，空袋就弹一句警告 —— 手上没旗的时候那一格等于废的。

现在它和建造托盘共用同一个托盘，只是内容换成**旗子卡**（同一套 `.tray__card` 木牌样式，
所以一眼就是"集市"的感觉）：

| 点 | 发生什么 |
| --- | --- |
| 旗子袋（空袋） | 托盘切成**旗架**：所有"盖好且有集合旗"的楼，一栋一张卡 |
| 旗子卡 | **拿过来**：旗进袋、直接进入落旗，托盘收起，格子写"点地面放旗" |
| 旗子袋（手上有旗） | 还是老行为：直接进落旗（不让你多点一步） |
| 地面 | 落旗，卡片副行更新成新的集合点 |

卡面两行：`兵营的旗` / `17,23`（集合点坐标）；手上那面显示 `在手里`、金边高亮。
实测：空袋点开 → 1 张卡 → 点卡后 `flagState=placing`、`held=2` → 落旗后 `rally={col:20,row:26}`。

顺手把 debug 读数挪到**右上角**（它之前被托盘压住了）—— 这块被挪过三次，
每次都只看自己不看邻居。这次用矩形相交实测：`hitsTray=false, hitsBar=false`。

### 信息卡：左边"它是谁"，右边"成本 / 产出 / 人手"

### 资源一律画图标，不写字

而且中文两个字就把卡片撑宽一截。

现在 `StatRow` 里的值是一组 `{ icon, text }`：图标走 `icons.ts` 那套（`resourceIcon` 映射），

| --- | --- |

`buildingFacts`（气泡里那份文字版）没动 —— 气泡是"念给人听"的，卡片是"扫一眼"的。

### 旗帜：路径砍到只剩一条（重新规范化）

上一版我留了三条取旗的路，互相串：

1. 点头顶那面旗 → 收进袋（`stowFlag`）；
2. 点旗子袋 → **袋里有旗就直接进落旗**（`armFlag`，我当"少一步"的便利加的）；
3. 旗架里的卡 → 拿旗 + 进落旗。

结果玩家看到的是"几个界面串在一起"：先点了头顶的旗，再点旗子袋，跳过的却是旗架，
直接变成"点地面放旗" —— 到底先点哪个完全说不清。

现在**只有一条**：

```
旗子袋  →  旗架（旗子卡）  →  点卡  →  点地面
```

- 旗子袋只做一件事：打开/收起旗架（不再看袋里有没有旗）；
- 头顶那面旗**不是第二个入口**：点它等于点旗子袋（同一个 handler），并且它不参与取旗状态；
- `stowFlag` / `armFlag` 两个方法直接删掉 —— 少一条路，就少一处能对不上的状态；
- 落旗后旗架自动收起（手空了就别留一排"在手里"的旧卡）。

实测四步：`旗架开 1 张卡` → `点卡 → placing/held=2` → `再点旗子袋 → 旗架重新打开、卡片标"在手里"` → `点地面 → rally=(20,26)`。

### 兵营为什么抽不到（不是 bug，是设计错了）

实测 600 抽的分布：**兵营卡（征兵令，史诗档）只出 16 次（2.7%）**。
玩家一局抽个两三次十连，摸不到兵营的概率超过一半 —— 军队这条路被压在运气上。

改了两处：

1. **征兵令从史诗挪到稀有**，权重 26（稀有带 0.27 × 26/172 ≈ 4.5%/抽）；
   兽穴（兽人小队）同理挪过去，权重 12；
2. **开局直接送一张兵营许可**（和议事厅一样）—— 成军是核心路径，不靠抽。

卡池锁跟着改了字据：精英带 148 → 108（兵营 26 + 兽穴 14 挪走），测试里写明了日期与理由。

### 屋顶浮在墙上（四栋）

用户说"有些建筑物是悬空的"。截图一看：不是楼浮在地面上，是**屋顶浮在墙上**。

| 楼 | 屋顶底面 | 墙顶 | 缝 |
| --- | --- | --- | --- |
| 兵营 | 0.94 | 0.55 | **0.39** |
| 精炼厂 | 0.90 | 0.54 | **0.36** |
| 弓手营 | 0.62 | 0.37 | **0.25** |
| 神龛 | 0.63 | 0.49 | **0.14** |

根因是同一个锚点约定：`prism / plinth` 的 `at` 是**底面**，`box / cyl / cone / sphere` 的 `at` 是**中心**。
这四栋的墙都按"底面"写了（0.12~0.2），其实整面墙陷进地里，屋顶就悬在墙顶上方。

原来的回归锁"没有悬空的件"抓不到它，因为那条只看竖直方向：一根细柱子从 0.1 顶到 0.9，
浮在 0.63 的屋顶也算"被柱子托住"。新锁换成"托件要压得住"：

- 托件顶面够到件底（±0.09）**且**覆盖件底 25% 以上，或件心正对它；
- 三根以上角柱可以合计（箭塔、矿井、工地的四根柱子撑一片屋顶就属于这种）；
- 或者件整根插在托件里（烟囱横管）、件心落在托件体积里（挂在墙上的轮毂、套在炮管上的铁环）。

## 对战模式（/arena.html）

用户 2026-10-27 的判断是"抽卡那套不好玩"，于是另起一套：素材共用、逻辑全新。
设计路线是**以建筑为主、军队为辅** —— 建筑贵但能一直产出，军队便宜但会死。

- **双方核心**：蓝（你，下方）/ 红（电脑，上方），各 1200 血，**拆掉对方核心才赢**。
  核心头顶挂一颗同色水晶，远远就能认出要守的是哪座。
- **20 点金**：上限 20、开局 5、每秒 +1.2（满金约 12.5 秒）。
- **四张手牌**：随机发，打出后该槽进 2.2 秒冷却再补一张。配卡组留到以后。
- **卡池六张**（价格 2026-10-27 按用户要求全部翻倍）：兵营 12（每 6 秒自动出兵，不花金）·
  箭塔 10 · 炮塔 14 · 磨坊 8（每 5 秒 +2 金）· 弓箭手小队 6 · 兽人 8。
- **建筑没有寿命**：不会自己掉血、不会定时消失（这是和老外的皇室战争刻意不同的地方），
  只能被兵拆掉。
- **出兵旗**：兵营有一个出兵点（地上插旗）。点自家兵营 → 再点地面，就把旗挪过去。
- **敌方 AI**：先建筑、后军队 —— 和玩家走同一套出牌规则（`execute`），只是没有手牌。

实机读数（Chromium 里跑真页面）：核心水晶颜色 `#7cc4ff / #ff8f7a`；
一座兵营 7 秒内出第一个兵；AI 前 40 秒会先立起箭塔/磨坊；
金币从 5 涨到 20 停住；手牌四张、打出扣费并进冷却补牌。
逻辑全在 `src/arena/ArenaWorld.ts`（不 import three、不碰 DOM），
`tests/arena.test.ts` 15 条锁在 node 里把一局跑完。
